# 图纸识别 + 3D 建模 能力评估与升级方案

> 评估日期 2026-08-01｜数据源:生产库实测(上海大歌剧院 2309 张竣工图)
> 模型版本 v30(2026-07-29 构建)｜识别版本:Phase I 全项目跑通
> 口径:**全部数字来自实测查询,不引用设计意图**

---

## 0. 一句话结论

单图识别精度已经很高(轴号圈 100%、轴线 95%、轴号 99/99、世界坐标 RMSE 6.1 毫米),
但**这些成果一条都没有流进 3D 模型**——识别出的 57611 条轴线,
在模型 13 个楼层里 **12 层的 `axes` 字段是 null、1 层是空**。

建模端 54.0% 的图纸进入楼层并产出构件,但**板的真实恢复率是 0**
(每层恒为 2 块,全部来自两个降级兜底,详见 §2.C)。

瓶颈不在"单张图看不懂",而在**链路没接通**。

## 2. 三个卡口(按影响排序)

### 卡口 A — 世界坐标只有 1 张图有(0.04%)

**现象**:122 张图有 `transform`,但只有 1 张有 `anchors`。

**根因**:世界锚点来自**坐标标注引线**,而坐标标注只画在少数定位图上。
这是**制图习惯决定的天花板**,不是算法缺陷——按现路线,再优化也只能覆盖那 122 张。

**但原料是充足的**:1484 张图的 57611 条轴线**全部带轴号**,
轴号 `1` 出现在 **1312 张图**上,`A` 出现在 **1084 张图**上。
轴网是跨图不变量——**一张图定到世界坐标,其余可以传递过去**,
不需要每张图都有坐标标注。

**已具备的基础**:`services/axis_world_anchors.transform_from_axes(axes, page_h, scale_m_pt)`
已经能从轴线反算变换;`services/drawing_anchor.py` 的相似变换已支持反射
(工程坐标 X=北/Y=东 是左手系)。缺的是**跨图传递这一环**。

**歧义风险(必须处理)**:分区号只确认了 3 个,其余图的轴号是**裸标签**
(`1` 而非 `1-1`)。A-01-02A 一张图有 3 个分区,`1-1` 与 `2-1` 都会退化成 `1`。
这正是此前修过的「未确认分区号时锚点串图」的规模版。
**不能靠人工确认 1484 张图**(每图 1~3 次,成本不可接受)。

### 卡口 B — 46% 图纸楼层识别不出,进人工队列

1061 张图落在 UNZONED,`issue_type: story_unclassified`。
这才是真正阻断构件提取的一环(不是 `semantic_unassigned`)。

**关于 `semantic_unassigned` 的诊断**:1866 张全部复跑仍 0 候选(可复现),
但把它算作"损失"是**需求错配**:

| 未分配图的构成 | 数量 | 占比 |
|---|---:|---:|
| 含「层」(有楼层、缺单体) | 842 | 45.1% |
| 详图 / 大样 / 放大 | 325 | 17.4% |
| 楼梯 | 149 | 8.0% |
| 说明 / 表 / 材料做法 | 122 | 6.5% |
| 含 南区/北区 | **0** | **0%** |

样本:`01施工总说明`、`02 环境总平图`、`03 分区平面示意图`、
`09围护桩配筋详图`、`10围护体剖面图(一)`……

后三类(详图/楼梯/说明表)以及围护基坑图,**本来就没有单体归属**,
应当标为 `not_applicable` 而非 `unassigned`,不计入损失。
真正值得处理的是那 842 张「有楼层、缺单体」的图——
标题里 0% 出现南区/北区,靠标题正则无解,应当**降级挂到默认单体**而非丢弃。

### 卡口 C — 板的真实恢复率是 0

`element_stats` 显示 13 层里 10 层的 `slabs` **恒等于 2**,这不是识别结果。
追 `_find_slabs` 的三条路径:

1. **图层命中**(`classify_by_layer(layer, block) == "slab"`)——
   E3-0 审计已证实这 2309 张图**全部是 PDF、无图层**,此分支**永远命中不了**
2. 降级:「最大闭合多边形」当整层单板 → 每图 1 块
3. `ensure_slab_from_columns` 柱包络补底板 → 每图 1 块

**每层恰好 2 块 = 路径 2 + 路径 3 两个兜底的产物。21 块板里,0 块是真板。**

后果:算量与碰撞检查实质未投产
(`model_quantities` 2 条、`model_topology_relations` 0 条)。

## 3. 升级方案

**执行顺序:U2 → U3 → U1 → U5,U4 降级为非阻塞。**
U2 代价最小当天可见,U3 解掉一个错误前提,U1 是最大杠杆但工作量也最大。

### U1 — 轴网跨图配准(最大杠杆,工作量也最大)

**目标**:把世界坐标覆盖从 1 张扩到 1484 张。

**做法**:不靠标签唯一性,靠**几何指纹**。
轴网的**间距序列**是跨图不变量且无需人工确认分区号:

1. 每张图提取「按法向偏移排序的轴线间距序列」作为指纹
2. 与已定位母图(A-01-02A,RMSE 6.1mm)做序列匹配(容忍缺失/多余轴线)
3. 匹配成功 → 由同名轴线对求相似变换(已有 `transform_from_axes` + 反射支持)
4. 残差门控:RMSE 超阈值标 suspect,不写库(此前 105m 残差被 suspect 正确拒绝,机制已验证)

**为什么可行**:间距模式比标签更具判别力——3 个分区的轴号会撞,但间距序列不会。

**预期**:世界坐标覆盖 0.04% → 目标 60%+(受限于 1484 张有轴网的图)。
这是**唯一一个能同时解锁定位、算量、碰撞的动作**。

### U2 — 轴网入模 ✅ 已实施(2026-08-01)

**先更正一个误诊**:builder 的 wiring 其实是**完整的**
(`_load_recognized_axes` → `recognized_axes_by_drawing` → `axes_to_scene` → `_merge_axes`)。
模型 v30 建于 **07-29 23:51**,而全项目识别是 **07-31 07:09** 才跑的——
**模型比识别早 1.5 天**,`axes` 为 null 只是因为模型没重建过,不是断线。

真正的闸是 `axes_to_scene` 里的 `zone_label_confirmed`,而全项目只有 **1 张**
图确认过分区号。

**已做的改动**——按国标放宽这道闸:

> §8.0.5 的分区编号**只在多分区时才用**。一张图只有一个分区时,
> 轴号 `1` 就是 `1`,不存在 `1-1` vs `2-1` 撞身份,人工确认无信息可加。

| | 改前 | 改后 |
|---|---:|---:|
| 单分区图视为已确认 | 否 | **是** |
| 可入模的图(单分区 + 有变换) | 1 | **302** |
| `zones_pending_label`(单分区图) | 1 | **0** |

实测重跑 `S-0-20-102.01C`:65 条轴线全部 `confirmed=True`,`needs_confirmation=False`。

**顺带修掉一个"为错误理由通过"的测试**:`test_anchors_need_a_confirmed_zone_label`
的注释讲的是「两个分区会撞身份」,用的却是**单分区**夹具——
而单分区图根本不存在冲突。已换成双分区夹具,并补 3 条新测试。

改动:`services/axis_recognition.py`、`tests/test_axis_recognition.py`、
`apps/web/src/services/projectInfo.ts`、`AxisRecognitionPanel.tsx`
(单分区不再向用户要一个他给不出的输入)。回归 **2345 passed / 3 skipped**。

**剩余动作**:全项目重跑识别(让 302 张生效)+ 重建模型。

### U2.5 — 衔接面审计(2026-08-03)

**识别结果的下游只有两个**:`services/model_builder.py`、`services/model_elements.py`。
审计结果:

| 消费方 | 接了吗 | 说明 |
|---|---|---|
| 建模 · 轴网入 scene | ✅ | `_load_recognized_axes` → `axes_to_scene` → `_merge_axes`,链路完整 |
| 建模 · 坐标变换 | ✅ | `fetch_project_transforms` 读 `drawing_transform`(1443 张有记录) |
| 建模 · 档案标高 | ✅ | 实测本次构建 `section-z 从档案读标高: 17/24 剖面图命中` |
| **AI 审图 · 轴号定位** | ❌ **未接** | 见下 |

**AI 审图的缺口**:`AIIssue.location.axes` 是**对问题文本跑正则**抽出来的
(`review_audit/location_extractor.py`),**从不与识别出的真实轴网核对**。
AI 说「1-A 轴处梁配筋不足」,没有任何环节验证这张图上是否真有 `1-A` 轴。

**但现在不做**:实测 23419 条审图问题中,**带轴号定位的是 0 条**——
`review` 引擎在本项目上没产出过轴号。给 0 行数据造校验器是空转(YAGNI)。
等 `review` 引擎在本项目跑出轴号定位后再接,那时校验器才有输入。

### U2.7 — 档案噪声压过识别轴号(真缺陷)✅ 已修(2026-08-03)

**现象**:`_merge_axes` 只在旧标签**为空**时才升级。而
`_attach_floor_elements` 里档案先合、识别后合——档案标签非空,
于是识别出的真轴号**永远覆盖不掉档案噪声**。

**档案 axis 是什么质量**:43643 条,覆盖全部 2309 张图,是未经校验的 OCR 原文。
实测样本:

```
IX | 80 | 3 | 1 | 0 | 4 | BY | M | E | P | S | A
```

- `IX` —— 含 §8.0.4 明令禁用的字母 `I`,不可能是轴号
- `80 / 3 / 1 / 0 / 4` —— 尺寸碎片
- `BY / M / E / P / S / A` —— 正是 Phase I 查明的**图框专业代号**

识别路径的轴号由几何推导 + 国标校验得来(全项目违规 0 条)。

**修法**:`_merge_axes(..., authoritative=True)`——识别标签覆盖档案标签;
空标签仍然永不覆盖已有标签(旧行为保住)。5 条新测试。

### U2.6 — 板的来源可辨识 ✅ 已实施(2026-08-03)

板有四种来源,此前**全部混在一个 `slabs` 数字里**:

| 来源 | 是识别吗 | 常量 |
|---|---|---|
| 图层/块名判定 | **是** | `SLAB_BASIS_RECOGNISED` |
| 最大闭合多边形 | 否(兜底) | `SLAB_BASIS_LARGEST_POLYGON` |
| 轴网包络 | 否(兜底) | `SLAB_BASIS_AXIS_ENVELOPE` |
| 柱/桩包络 | 否(兜底) | `SLAB_BASIS_COLUMN_ENVELOPE` |

`element_stats` / `totals` 现在多报一个 `slabs_recognised`。
缺 `basis` 的旧数据按**兜底**处理,绝不默认算成成果。

这不改变任何几何,只让「21 块板」这个数字说实话。

### U3 — 板恢复:换掉"靠图层"这个前提(E3-4)

现有 `_find_slabs` 的主路径依赖图层名,而本项目 100% 是无图层 PDF——
**这个前提在本项目上永远不成立**,所以不是"调参数"能解决的。

正确做法是补一条**不依赖图层**的路径:
从闭合多边形的几何特征(面积、长宽比、与柱/墙的包含关系、
与轴网的对齐度)判板,而不是从图层名判板。

同时把两个兜底显式标注成 `src: fallback`,让 `element_stats` 能区分
"识别出来的"和"兜底补的"——现在这两者混在一个数字里,
21 块板看起来像成果,实际是 0。

### U4 — 全字符识别(降低人工依赖)

分区号目前必须人工确认。OCR 在坐标数字上置信 0.96~1.00,
但在轴号字符上只有 1/24——**差别在字号**。
若 U1 成立,分区号确认的必要性会大幅下降(几何指纹不需要它),
所以 **U4 的优先级应当下调**,不再是阻塞项。

### U5 — 人审通道空转(0 条 verified)

档案层的 auto/verified 分离、返工点埋点、审校队列都建好了,但**没人走**。
这不是技术问题,是投产问题。建议先不投入新开发,
等 U1/U2 把模型质量抬上去、有东西值得审了,再看是否真的需要。

## 4. 对「≥90% 识别率」目标的诚实回答

用户设定的前置条件是:PDF 路线准确识别 ≥90% 图纸内容,才考虑 DWG 路线。

按不同口径:

| 口径 | 实测 | 距 90% |
|---|---:|---|
| 识别任务完成率 | 100% | 已达标(这个口径没有意义) |
| 识别出轴网的图 | 64.3% | 差 26 个点 |
| **进入楼层并产出构件的图** | **54.0%** | **差 36 个点** |
| 有世界坐标的图 | 5.3% | 差 85 个点 |
| 轴线进入 3D 模型 | **0%** | 差 90 个点 |
| 板的真实恢复率 | **0%** | 差 90 个点 |
| 单图轴网精度 | 95~100% | 已达标,但**样本只有 3 张** |

**结论:尚未达到 90%,不应启动 DWG 路线。**
差距不在单图精度,在**链路贯通**(U2)与**依赖图层的旧前提**(U3)。

## 5. 能力边界(不夸大)

- 单图 95~100% 的成绩来自 **3 张图**(A-01-02A / 03A / 04A),不代表 1484 张的分布
- **识别出的轴线一条都没进 3D 模型**(12/13 层 `axes` 为 null)
- **板的真实恢复率 0**:21 块全部来自兜底,主路径依赖图层而本项目 100% 无图层
- `model_story_levels` / `model_topology_relations` 两张表在真实项目上是**空的**
- 外轮廓识别:**未实现**。已查清外轮廓画在 A-02-02A(板边控制线,0 弧,折线为主)
  和 A-02-03A(扇形屋盖结构边线,3 条弧 R=1634/572/485pt)上,
  轴网定位图 A-01-02A 矢量层面**一条弧都没有**
- 用地红线:本项目 2309 张图**没有一张总平面图**,故不存在用地红线。
  GB/T 50001 §4.0.2 只定义**细线**用途,粗/中长画线原文写「见各有关专业制图标准」;
  用地红线线型归 GB/T 50103《总图制图标准》,**本机无此标准,未核**
- GB/T 50104《建筑制图标准》47 页**无文本层**,至今未读入
- 极坐标轴网:圆心已能定到 1.2pt、107/107 圈覆盖,但**尚未接入生产链路**
- 算量/碰撞:`model_quantities` 2 条、`model_topology_relations` 0 条,**实质未投产**
