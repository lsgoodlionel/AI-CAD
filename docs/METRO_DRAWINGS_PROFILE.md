### 2.4 `drawing_role`「零编号知识判出 89.1%」是否失效？

**结论：不失效，实测 85.6%，比大歌剧院低 3.5 个百分点——但这不是重点，重点是它下游崩了。**

把 `drawing_role._by_term` 的 9 条正则（Tier 2，完全不看图号）原样跑在 1798 个图名上：

| 角色 | 数量 | 占比 | 实例 |
|---|---|---|---|
| detail | 685 | 38.1% | 地下连续墙预埋件详图 |
| component_source | 437 | 24.3% | 围护体平面布置图 |
| non_geometric | 350 | 19.5% | 基坑围护设计施工总说明 |
| **unknown** | **259** | **14.4%** | 周边管线平面关系图、A型埋件加工图 |
| elevation_reference | 67 | 3.7% | 地下连续墙配筋立面图（一） |
| **coordinate_base** | **0** | **0.0%** | — |
| **floor_skeleton** | **0** | **0.0%** | — |

**Tier-2 覆盖率 = 1539/1798 = 85.6%**（大歌剧院 89.1%）。术语判据本身**是通用的**——因为它判的是 GB 图名术语，不是图号。这条设计约束经受住了检验。

**但真正的问题在 `partial_set.assess_capability` 的下游**：

```
coordinate_base    = 0  ->  P0 世界坐标 = none   「无坐标基准图…没有世界坐标」
floor_skeleton     = 0  ->  P1 楼层     = partial 「无完整平面图——楼层由专业平面图的图名归纳，可能缺层或分层不准」
elevation_reference= 67 ->  P2 标高     = full
component_source   = 437 -> can_build   = True
```

即：**仅靠图名，这批图纸拿不到任何 `coordinate_base` 和 `floor_skeleton`**。原因是那两条正则写死了大歌剧院的图名习惯：

- `coordinate_base`: `轴网.*定位图|定位图.*轴网|轴线定位|坐标定位` — 本语料**零命中**（该设计院不用"定位图"这个词，`A-01-03A-基地总首层平面图` 才是总平面基准图）
- `floor_skeleton`: `完整平面图|平面总图|整体平面` — 本语料**零命中**（该设计院写 `A-10-12B-九层平面图`，不写"完整"）

`drawing_role` 还有 Tier 1（内容判据，20 个轴号圈 / 200 个构件 / RANSAC 内点 ≥5）可以救回 `coordinate_base`。抽样测得 **35.7% 的页有 ≥20 个 8~10mm 圆**，所以 Tier 1 有机会兜住。但见 §8 风险 R6：这些"圆"里混着大量机电点位符号。

**259 张 unknown 高度集中在幕墙**：`A型埋件加工图`（加工图不是任何一种视图）、`GRC后置埋件立面布置`（"立面布置"缺"图"字，正则 `立面图` 不匹配）、`C2钢件布置图`、`采光顶铝型材构件布置示意图`。这是**幕墙专业词汇缺口**，不是编号问题。

### 4.3 矢量文字 —— OCR 路线 vs 矢量路线

抽样 288 张，统计第 1 页的 text span 数：

| span 数 | 数量 | 占比 |
|---|---|---|
| 0 | 2 | 0.7% |
| **1–9** | **189** | **65.6%** |
| 10–49 | 36 | 12.5% |
| 50–199 | 50 | 17.4% |
| 200+ | 11 | 3.8% |

**只有 33.7% 的页有 ≥10 个 span。**

那 65.6%「1–9 span」的页里装的是什么？**全是页脚水印**：

```
189×  '上海建工四建集团有限公司'
189×  '上海建浩工程顾问有限公司'
 90×  '2020-06-22'   （及其它出图日期）
```

即：**图面本体的文字（轴号、标高、尺寸、房间名）已被转成曲线，取不到**——与大歌剧院同源。

> ⚠️ **这是一个陷阱**：`page.get_text()` 对 **99.7%** 的页都返回非空字符串。任何形如「有文字 → 走矢量路线，跳过 OCR」的开关，会对 65.6% 的图纸做出**错误判断**，拿到 4 条水印就以为读到了图。判据必须是 **span 数 / 正文区 span 数**，不是 `len(text) > 0`。

### 4.5 文字乱码（全新失效模式）⚠️⚠️

有文字的 262 张里，**77 张（29.4%）含 ≥3 个乱码字符**（PUA / CJK 扩展 A / 控制字符），典型：

```
基坑支护-竣工图-13-剖面图（三）.pdf
  提取结果: 'ᐛぁ䇴䇗⭨㓝\x03䇷Ҝ㕌ਭ\x03$\x14\x16\x14\x13\x13\x17\x13\x16\x14 …'
  真实内容: '建筑设计资质 证书编号 A131004031 …'（推测）
```

成因是**未嵌入 ToUnicode CMap 的子集字体**——字形能画对，但字符码到 Unicode 的映射丢失。

大歌剧院是「**文字取不到**」（安全，会自动降级到 OCR）；这里是「**文字取得到但是错的**」（危险，会静默污染档案层）。剩余 185 张（70.6%）是干净中文。

**归档层没有任何机制区分这两者。**

## 8. 预测：哪些现有判据会在这批图上失效（按风险排序）

### 🔴 R1 — CRITICAL：`_MULTI_SEGMENT_NO_RE` 在 `C1-H01` 形态上崩溃，造成 23% 图号撞号

**判据**：`services/drawing_filename_parser.py`
```python
_MULTI_SEGMENT_NO_RE = r"[A-Za-z]{1,3}(?:[-_]\d{1,4}(?:\.\d{1,2})?){2,4}[A-Za-z]?"
_DRAWING_NO_RE       = r"[A-Za-z一-龥]{1,4}[-_ ]?\d{1,4}"
```

**失效机理**：`C1-H01` 的第一段是「字母+数字」，`[A-Za-z]{1,3}` 后面紧跟的是 `1` 而不是 `-`，多段正则不匹配。退到 `_DRAWING_NO_RE`——而该正则**包含 CJK**（`一-龥`），从左往右扫，最先命中的是 `C1`，于是 **130 张不同的图纸全部得到 `drawing_no = "C1"`**。

**实测**：

| 指标 | 值 |
|---|---|
| 语料真实图号唯一性 | **1724/1748 = 98.6%**（语料本身是干净的）|
| 解析后撞号 | **414 张（23.0%）** |
| 撞号的不同号码 | 49 个 |
| `C1` | **130 张** |
| `C2` / `C5` / `C4` / `C3` / `C7` / `C6` / `C8` / `C9` | 64 / 61 / 20 / 13 / 13 / 11 / 11 / 5 |
| 幕墙目录撞号率 | **376/489 = 76.9%** |
| 机电 / 建筑 / 其余 | 5.6% / 3.7% / 0% |

**另有 233 张（13.0%）图号被解析成明显错误的值**——`_DRAWING_NO_RE` 含 CJK 导致把「竣工图」本身当成图号：

```
'基坑支护-竣工图-01-基坑围护设计施工总说明'  ->  drawing_no = '竣工图-01'   ❌
'基坑支护-竣工图-09A-地下连续墙预埋件详图'   ->  drawing_no = '竣工图-09'   ❌
```
且置信度仍报 **0.95**。

**影响面**：`drawing_no` 是 Phase H「统一轴号为主键的数据关联」的一个关键关联键，也是 `drawing_role` Tier-3 学习编号段的输入（`_SEGMENT_RE` 会把 `C1` 切成空前缀）。23% 主键冲突会静默污染整条装配链。

### 🔴 R3 — CRITICAL：`sub_unit_discovery` 从 `负1F` 造出幽灵单体「负」

**判据**：`services/sub_unit_discovery.py`
```python
_FLOOR_TOKEN_RE = r"(B\d{1,2}|\d{1,2}F|\d{1,2}层|…)"
_PREFIX_OK_RE   = r"^[^/:：;；\-（）()，。.]*[一-鿿][^/:：;；\-（）()，。.]*$"
MIN_PREFIX_OCCURRENCES = 2
```

**失效机理**：`负1F` 中 `\d{1,2}F` 从 index **1** 开始匹配 → 前缀 = `负`。`负` 含 CJK ✓、无禁用标点 ✓、出现在 `负1F`/`负2F`/`负3F` 三个不同楼层名上 ≥2 ✓ → **判定为一个合法子单体**。

**实测**：`负` 出现 **23 次**，是候选前缀的第一名（第二名仅 2 次）。另有 `出`、`北面`、`电缆`、`12负`、`负一、` 五个噪声前缀。

**后果**：`level_elevation_consensus` 按 `(unit, level)` 分组，且**图名内嵌单体名优先于外部分类器**。一个不存在的「负」单体会把地下三层的标高共识从主单体里劈出去，`MIN_WITNESS_DRAWINGS=2` 的见证图数被稀释，标高恢复静默退化。

**根因**：楼层 token 正则没有把「表示负号的前缀字符」纳入 token 本身。这是 `负nF` 记法第一次出现。

### 🟠 R5 — HIGH：`page.get_text()` 非空 ≠ 有可用文字（65.6% 假阳性）+ 29.4% 乱码

### 🟠 R6 — HIGH：`MIN_CIRCLES_FOR_BASE = 20` 会把机电点位图误判为坐标基准图

**判据**：`services/drawing_role.py::MIN_CIRCLES_FOR_BASE = 20`（大歌剧院实测定位图 107~285 个轴号圈）

**实测**（抽样 263 张，按 8~10mm 直径 = 18~40pt 近圆闭合曲线计数）：

| 指标 | 值 |
|---|---|
| 圆数 min / p25 / 中位 / p75 / max | 0 / 1 / 6 / 38 / 181 |
| **≥20 个圆的页** | **94/263 = 35.7%** |

但圆数最高的几张是：

```
181  机电/弱电/弱电-竣工图-E-25-01A-地下三层层综合布线，有线电视平面图
153  机电/装饰给排水/…-P-31-03-一层给排水消火栓平面图
132  机电/给排水/…-P-21-01-地下三层给排水平面图
129  机电/电气/…-E-51-08B-五层消防电源、防火门与电气监控平面图
128  建筑/建筑-竣工图-A-10-12B-九层平面图          ← 只有这张是真的轴号圈密集
```

**弱电平面图上的 181 个"圆"是烟感/广播/摄像头点位符号**，不是轴号圈。由于 R4 让术语路径给不出 `coordinate_base`，Tier 1 成了唯一通道，而它会**优先选中机电点位图当坐标基准**。

大歌剧院机电图相对少，未暴露此冲突。

### 🟡 R7 — MEDIUM：25.5% 页面旋转，坐标系可能整体偏

`/Rotate = 270` 占 24.7%，`90` 占 0.8%。`page.rect` 已归一化，但 `get_drawings()` 与 `get_text("dict")` 的坐标是否需要 `derotation_matrix` 取决于调用方式。`drawing_transform`（migration 031，pt→米）与 `title_block_template.aspect_bucket(w/h)` 都直接吃页面几何——**旋转会让长短边互换，aspect_bucket 把同一种图框分裂成两个模板**。

大歌剧院语料未暴露（本次未测其旋转分布，但相关缺陷从未被报告过）。

### 🟡 R8 — MEDIUM：`title_block_template.aspect_bucket` 把 21 种图幅压成少数几个桶

**判据**：`services/title_block_template.py`
```python
aspect_bucket(w, h) = round(w/h, 2)   # _ASPECT_PRECISION = 2
```

**实测**：A0/A1/A2/A3/A4 的长宽比都 ≈ **1.41**，全部落进同一个桶。而 21.7% 的加长图幅比值分散在 1.75~2.80，会各自开新桶。

后果：
- 在 A3 上学到的图框字段区域，会被套用到 A1、A0（面积差 8 倍）
- 加长图幅（`4796×1712`，比值 2.80）每种开一个桶，图框记忆无法跨图幅复用 → Phase H「图框字段区域记忆，框一次跨项目复用」在这批图上复用率大幅下降

### 🟡 R9 — MEDIUM：`layer_class_map.yaml` 面对 2673 种真实图层名，覆盖率未知

图层从"不存在"变成"存在且丰富"是**机会**，但现有映射表是在**没有真实图层可测**的前提下写的。三个必须先解决的解析问题：

1. 中文图层名用**全角破折号 U+2014**（`I—平面—文字`、`C—图框—文字`），按 ASCII `-` 切分整段失败
2. **xref 绑定前缀** `AXIS_B03_150$0$0S-AXIS`，须先剥 `NAME$0$` 才能认出 `S-AXIS`
3. 仅 **2.2%** 图层名符合 AIA/专业编码模式；**47.7%** 含中文；`0`/`1`/`8`/`图层1`/`图层 1` 是高频无信息噪声

这是 R 系列里**唯一一条"做对了会变好"**的，其余都是"会变坏"。

### 🟡 R10 — MEDIUM：装饰标段机电 150 张与主体机电混淆

`机电/装饰电气`(75) + `机电/装饰暖通`(38) + `机电/装饰给排水`(37) = **150 张**，全被 `_detect_discipline` 判为 `mep`（关键词表中"电气/暖通/给排水"组排在"装饰"组之前）。

它们与 `机电/电气`(179)、`机电/暖通`(77)、`机电/给排水`(79) 是**两套独立图纸**，且**图号前缀完全相同**（都用 `E-` / `M-` / `P-`），甚至号段重叠。系统没有"标段/承包段"这一维，两套图会被当成同一套的不同版本。

### ⚪ R11 — LOW：版本号 77.4% 静默默认为 'A'

`_TRAILING_REV_RE = r"\d([A-Z])$"` 只能从**已提取的图号末尾**取版本。实测：

- 文件名中确有版本字母的：391 张（21.7%）
- 解析器实际取到的：406 张（22.6%）
- **静默落 `DEFAULT_VERSION = 'A'` 的：1392 张（77.4%）**

装饰的 `I-14-01-A -1F平顶尺寸图`（版本 `A` 在独立字段）碰巧对上了，但那是巧合。`鲁班奖修改` 目录里同图号两版（`A-70-02A` 出现 2 次）无法区分先后。

### ⚪ R13 — LOW：`_EXCAVATION` 的 `地铁` 关键词在真地铁项目上会灾难性误判

`building_unit_fallback._EXCAVATION` 含 `地铁`，命中即判 `not_applicable`（临时工程，不建模）。

本项目仅 2 张命中（`9F地铁热线中心立面图`，装饰图，无害）。但**在真正的地铁车站项目上，几乎每张图的图名或图框都含「地铁」，整套图会被判为不建模**。

本次语料**没有**真地铁车站图纸，所以这条**未被检验**——但它是已知的定时炸弹。
