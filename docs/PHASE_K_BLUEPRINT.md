# Phase K｜以轴网为工程自有坐标系的 3D 定位

> 立项日期：2026-08-20
> 前序：Phase J 主线「世界坐标规模化」实测受阻（见 `PHASE_J_BLUEPRINT.md` §8.35）
> 一句话：**放弃「先有世界坐标才能定位」的前提，改用图纸本身就有的轴线与标高定位。**

---

## 1. 为什么改方向：一组数字

| | 上海大歌剧院 | 轨道交通工程 |
|---|---|---|
| 图纸总数 | 2309 | 1798 |
| **有轴号的图** | 2309（**100%**） | 1710（**95%**） |
| 能由轴号定出坐标变换 | 727（31%） | 80（**4.5%**） |
| 轴线交点（世界锚点） | 5401 | **12** |
| **有世界坐标的图** | 11（**0.5%**） | **0** |
| `placed_drawings` | 29 | **0** |

**世界坐标（测量坐标）近乎没有，而轴号几乎每张图都有。**

这不是数据质量问题，是**施工图的固有属性**：
- 世界坐标只出现在总平面图、定位图这类少数图上（国标不要求每张图标）
- 而**定位轴线是每张平面图的必备要素**（GB/T 50001 §8：定位轴线用于平面定位）

所以「等所有图都有世界坐标」这条路走不通——**不是还没做到，是本来就不会有**。

## 2. 核心主张

> **工程自有坐标系 = 轴网 + 标高。**
> 轴号 `1/A` 的交点就是原点候选，轴线间距给出 xy 尺度，楼层标高给出 z。
> 全程不需要一个测量坐标。

这与现有能力的关系：
- `services/global_axis_consensus.py` 已能把多张图的同名轴号求出一致位置（中位共识 + 鲁棒对齐）
- `services/model_z_levels.py` / `level_elevation_pairing` 已能给出楼层标高
- **缺的是把这两者当作主路径**，而不是「世界坐标不可用时的降级」

## 3. 分阶段

### K-1 轴网帧（Project Axis Frame）

把全项目的轴号解析成**一套工程自有的坐标系**：

- 输入：各图的轴号 + 页面坐标（档案层 `axis` 分类，已有）
- 处理：按方向分组 → 同名轴号求共识位置 → 定出轴线间距 → 建立 `1/A` 为原点的帧
- 输出：`axis_frame`（每个轴号 → 帧内米坐标）

**判据**：轴号必须**双向都有**（数字轴 + 字母轴）才能定帧；
只有单向的图（剖面、立面）不定帧，按 §8.28 的既有结论走投影路径。

**验收**：两个工程各自能定出至少一个覆盖主体的轴网帧；
帧内轴距与图纸标注的轴距误差 ≤ 1%。

### K-2 每图对齐到轴网帧

- 输入：单图的轴号位置 + K-1 的帧
- 处理：匹配同名轴号 → 求相似变换（已有 `axis_pose_solver` / `pose_ransac`）
- 输出：该图的 `frame_transform`（页面点 → 帧内米）

**与现有 `drawing_transform` 的区别**：后者试图求「页面 → 世界」，
前者只求「页面 → 轴网帧」。**后者的参照物在图上，前者的参照物在图外。**

**判据**：至少匹配上 2 个数字轴 + 2 个字母轴才求解；
残差超阈值判 suspect（沿用现有门禁）。

**验收**：轨道交通「能定位的图」从 80 张（4.5%）提升到轴号可用图的多数；
对齐残差中位 ≤ 0.1 m。

### K-3 z 用标高

标高链已有（`elevation_m` 实测 -21.0~60.0 完整）。本阶段只做两件事：
- 把 `elevation_m` 作为构件 z 的**唯一来源**（现在部分路径仍用层序号推）
- 标高缺失的层**明确标记**，不用默认层高悄悄补（沿用「降级必须可见」）

### K-4 无轴号图的处置

详图、系统图、说明、表格**本就没有平面位置**——
不定位、不进楼层几何，只留在档案与语义树里。
**明说「这张图不参与三维定位」，而不是给它一个假坐标。**

## 4. 验收总标准

1. 两个工程的**可定位图纸占比**都显著高于当前（4.5% / 31%）
2. 场景包络 / 中间 90% 点的比值 ≤ 2（当前轨道交通 1.32、大歌剧院 3.99）
3. 同名轴号在帧内的位置一致（同 §8.33 的共识判据）
4. **不可定位的图有名有姓地列出来**，并说明原因
5. 全程不依赖任何测量坐标——有世界坐标的图作为**校验**而非前提

## 5. 已知风险

- **分区工程**：一图三套轴网（GB/T 50001 §8.0.5），帧要按分区建，
  否则 `1×A` 会在两个分区撞身份（§8.33 已踩过）
- **轴号识别质量**：轨道交通只有 12 个轴线交点，说明轴号识别在该工程上
  远不如大歌剧院（5401）。K-1 之前可能需要先补轴号识别
- **多单体**：南北区各有原点，帧要按单体建（既有 `_same_unit` 已有此纪律）
- **不要重蹈「判据只对部分对象生效」**：帧的规则必须对结构/建筑/机电
  一视同仁，不能只给某一类开口子

## 6. K-1 首轮实测（2026-08-20）

`services/axis_frame.py` 落地，两个工程实跑。

### 结果

| 口径 | 大歌剧院 | 轨道交通 |
|---|---|---|
| 全工程混建（不分组） | 进帧 4%，残差中位 **5.7 m** | 进帧 6%，残差中位 **7.6 m** |
| **按楼层+单体分组** | 进帧 **34%**，残差中位 **2.8 m** | 进帧 8%，残差中位 6.8 m |
| 分组后 **P25 残差** | **0.038 m** | 2.13 m |

### 三条结论

**① 分组是必要条件，不是优化项。** 立项时列为风险 #1，实测证实：
不分组时 96% 的图残差超阈值。同一个 `1×A` 在不同单体/分区是不同位置，
混着建帧没有任何一套坐标能同时满足。

**② 分布是双峰的，不是普遍误差。** 大歌剧院 P25 残差 **0.038 m** ——
**能对上的时候是厘米级**。中位 2.8 m 是被一批完全对不上的图拖高的，
不是所有图都差 2.8 米。所以方向没错，要做的是把那批图分出去，
而不是放宽阈值。

**③ 轨道交通受限于上游轴号识别。** 它的轴线交点只有 12 个
（大歌剧院 5401），分组后仍只有 8% 进帧。
**K-1 之前需要先补该工程的轴号识别**——这在立项风险 #2 里已列出，
现在有了数字。

### 排除掉的两个假设

- **不是比例问题**：只用可信变换（置信 ≥0.5）反而更差（4%→3%），
  说明比例不是主因。
- **不是页面翻转**：改用完整变换（含 `page_h - y`）后残差**一字未变**
  （5.678 → 5.678）。

### 下一步

K-1 的解算本身可用（P25 厘米级）。瓶颈在**分组粒度**与**上游轴号质量**，
而不在解算。下一步应先做「把对不上的那批图分出去」的判据，
而不是继续调解算。


## 7. K-1 第二轮：二维联合聚类（2026-08-20）

### 又一个「分向处理」的代价

第一轮按方向**分别**聚类：x 一套共识、y 一套共识，
再要求一张图两方向都符合才进帧。

实测最大的分组（UNZONED/main，399 张）**一帧都建不出来**——
连种子自己在 y 方向的残差都有 **2.99 米**：
它符合 x 的那一团，却属于 y 的另一团。

**帧是二维的东西，不是两个独立的一维系统。**
改为联合生长：一个池子，候选必须**同时**在两方向与它相容才并入，
一个方向不合就整张不收。

### 结果

| | 分向聚类 | 二维联合聚类 |
|---|---|---|
| 大歌剧院 进帧（含单成员） | 36% | **98%** |
| 大歌剧院 **帧≥2 成员** | — | **86%** |
| 大歌剧院 帧≥5 成员 | — | 68% |
| 轨道交通 进帧（含单成员） | 27% | **76%** |
| 轨道交通 **帧≥2 成员** | — | **53%** |
| 轨道交通 帧≥5 成员 | — | 26% |
| 残差中位 | 3.1 mm / 0 | **0.1 mm / 0** |
| 残差 P95 | 0.32 m / 0.30 m | **0.17 m / 0.12 m** |

**「进帧率」这个数字会灌水**：单成员帧（161 / 156 个）是一张图
自己跟自己对齐，残差当然是 0，却不构成任何交叉约束。
所以主口径应看**帧≥2 成员**：86% / 53%。

### 下一步

K-1 可以收口了：大歌剧院 86% 的图落在有交叉约束的帧里、
残差 P95 17 厘米。**K-2（每图对齐到帧）现在有可用的输入。**

轨道交通 53% —— 受限于上游轴号识别（轴线交点 12 个 vs 5401），
这一条在立项风险 #2 里已列，数字现在更明确了。


## 8. K-2/K-3：帧落库可用，但**帧间配准基本不成立**（2026-08-20）

### K-2 落库（成）

migration 049 两张表：`axis_frames`（分组键 + 帧号 + 轴号→米）、
`drawing_frame_placements`（每图平移量 + 残差 + **所在帧成员数**）。

`frame_size` 不是装饰：单成员帧残差恒 0 却不构成证据，
消费方按它折算可信度，否则「进帧率」会被灌水（98% vs 有约束的 86%）。

### K-3 帧间配准（**实测基本不成立**）

只读对照（不动生产数据）逐轮暴露问题：

| 状态 | 大歌剧院 比值 | 轨道交通 比值 | 落库摆放 |
|---|---|---|---|
| 现状（各图局部坐标） | 3.99 | 3.05 | — |
| 换到帧内（未配准） | 4.85 | 15.74 | 1394 |
| 修好偏移量总量后 | 4.98 | 8.42 | 1394 |
| 加帧间配准（不校验） | 4.98 | **2.73** | 1394 |
| 帧间配准 + 校验残差 | 1.01 | 1.24 | **157（11%）** |

**最后一行的比值是空的**：只剩 11 个构件（0%）和 1918 个（4%）。
数字漂亮是因为几乎什么都不剩。

### 结论

**帧内干净 ≠ 帧之间对齐。** 每个帧以「本帧最小轴号 = 0」为原点，
321 / 246 个帧就是同样多个互不相干的原点。

而帧之间**多数配不上**，这不是缺陷是事实：不同单体、不同分区
共用轴号名（`1`/`A`）却是**不同的轴网**。
强行配准要么污染（宽松）要么归零（严格）。

**所以现在不能把帧接进建模主路径**——只读对照就是为了在动生产数据前
发现这一点。K-1 的帧内成果（86% 覆盖、毫米级残差）仍然成立且已落库，
但要让它对最终模型有用，还缺**帧间的额外信息**：

- **楼层堆叠**：同一单体的不同楼层本就共用一套轴网（建筑是垂直对齐的），
  这类帧之间的配准是合法的
- **分区编号**：同一层的不同分区是不同轴网，**不该**配准
  （Phase I 已做过分区号人工确认，那个信息这里能用上）

下一步应按「同单体跨楼层可配准、同楼层跨分区不可配准」重做 K-3，
而不是让所有帧互相配准。

### 一个反复出现的坑：来者不拒

同一个错误在本 Phase 内出现了**三次**：
1. `_grow_consensus` 只看「有没有共有轴号」就并入 → 混两套轴网时返回 0 帧
2. 分方向聚类各自成团 → 最大分组一帧都建不出来
3. 帧间配准不校验残差 → 错配帧污染池子，包络 833→1079 米

**每一次的表现都不同，根因是同一个：拿「有没有关联」当成了「关联对不对」。**


## 9. K-3 重做与两个口径的分离（2026-08-20）

### 按结构关系决定谁能配准

上一版让**所有**帧互相配准，宽松则污染、严格则归零。
改为按建筑本身的关系先分好「谁跟谁有资格比」：

- **同一单体的不同楼层共用一套轴网**（建筑垂直对齐）→ 可配准
- **同一楼层的不同分区是不同轴网**（GB/T 50001 §8.0.5 一图三套）→ 不可配准
- **跨单体不可配准**（南区北区各有各的原点，配准会把两栋楼摞在一起）

### 我把两件事混了一次

改完之后落库摆放从 1394 掉到 171 —— 因为对未配准的帧直接不落摆放，
**把 K-1 的帧内成果也一起丢了**。

**帧内一致性与帧间配准是两件事：**

| 口径 | 含义 | 大歌剧院 | 轨道交通 |
|---|---|---|---|
| 帧内有交叉约束 | 同帧构件的相对关系可信（残差毫米级） | **86%** | **53%** |
| 帧间已配准 | 该帧在单体主轴网中的位置已知 | **12%** | **5%** |

现在都落库，用 `registered` 标出分界（migration 049 补列）。
消费方必须能区分：**帧内一致可用于同帧构件的相对关系，
帧间未配准则不能跨帧摆放。**

### K-3 的真实瓶颈

12% / 5% 不是解算不够好，是**信息不够**：321 个帧里只有 36 个是
各层主帧，其余是分区帧或局部小帧，它们与主轴网**本就没有共有参照**。

要提高这个数字，需要轴网之外的信息：
- **分区几何关系**（Phase I 已做过分区号人工确认，那个信息这里能用）
- **图框定位**（Phase H 的图框字段区域记忆）
- **人工指定**（少量锚定，撬动大量帧）

**在此之前，帧不接入建模主路径**——只读对照已证实接入会让模型变差。


## 10. K-3 第三轮：世界锚点两级配准（2026-08-20）

### 找到了此前被低估的锚点

`axis_intersections` 里 **5401 个交点全部带世界坐标**，覆盖大歌剧院
76 张图。此前记的「有世界坐标的图 11 张（0.5%）」是按
`drawing_transform` 口径，**低估了**。

锚点是**强证据**（轴号交点 → 实测世界坐标，Phase I 实测 RMSE 5.7 毫米），
帧间共有轴号是**弱证据**（两个帧碰巧都有轴号「1」不代表同一片轴网）。
两级配准：先用锚点钉，再让其余帧向**已钉住的帧**对齐。

### 一个混合参照系的坑

第一版让两级各自独立：锚点给测量坐标（几十万米量级），
轴号配准另起 0 点给帧内局部坐标——**混进同一场景内容被隔开几公里**
（包络 6563 米，而建筑实际约 200 米）。

修法：轴号配准以已钉住的帧为锚（`register_frames(seeds=…)`），
两级落在同一参照系里。代价是帧间配准率从 34% 回到 **16%**——
之前那 34% 里有一半在另一个参照系里，是虚的。

### 最终数字与决定

| 口径 | 大歌剧院 | 轨道交通 |
|---|---|---|
| 帧内有交叉约束 | **86%** | **53%** |
| 帧间已配准 | **16%** | 5% |
| 其中锚点钉住的帧 | 23 | 0 |

只读对照（三种情形）：

| 情形 | 大歌剧院 包络 / 比值 | 轨道交通 包络 / 比值 |
|---|---|---|
| 现状（各图局部坐标） | 833 m / **3.99** | 360 m / 3.05 |
| 只看已配准的 | **456 m / 1.36** | 192 m / 1.24 |
| **实际接入（混合）** | **1318 m** / 1.76 | 360 m / 2.99 |

**「只看已配准的」那一行证明方法是对的**——比值 1.36、包络 456 米，
对这个建筑群合理。

**但混合场景下不能接入**：比值 3.99→1.76 是假象，
包络反而从 833 涨到 **1318 米**。两片坐标云各自成团、体量相当，
比值就显得好看，绝对范围却更差。

### 接入的前提条件

帧要接入建模主路径，需要**整层整单体都已配准**，
而不是逐图混着换。当前 16% 的配准率还差得远。
提高它的路径已经清楚：
- 补更多世界锚点（当前 76 张图，人工标少量即可撬动整帧）
- 用 Phase I 的 220 条分区确认切开同层的不同轴网
- 用 Phase H 的图框定位给帧提供第二类锚
