# 图纸分类体系与分阶段建模流程蓝图

> 版本 V1.0 ｜ 2026-08-03
> 经验基础:上海大歌剧院 **2309 张竣工图**全量实测
> 国标依据:GB/T 50001《房屋建筑制图统一标准》、GB/T 50104《建筑制图标准》
> 目的:**大批量图纸导入后,按什么顺序识别、按什么顺序建模**

---

## 0. 核心结论

**骨架图只占 1.8%,却决定其余 98% 图纸的挂载位置。**

| | 张数 | 占比 |
|---|---:|---:|
| 骨架图(轴网定位 11 + 完整平面 8 + 剖面 16 + 立面 4 + 轴网 2) | **41** | **1.8%** |
| 其余(专业平面 / 详图 / 系统图 / 说明) | 2268 | 98.2% |

现有实现**不分先后一起跑**,于是构件先落到默认标高上
(实测 13 层里 10 层是 `4.5m` 硬推的,最大偏差 11.9 米),
之后即使读出真标高也来不及纠正。

**分阶段建模的核心不是效率,是依赖顺序**:
坐标系 → 楼层表 → 楼层轴网 → 构件 → 细节。
上游没定,下游做多少都要返工。

## 1. 国标依据

### 1.1 图纸编排顺序(GB/T 50001 §3.3)

> **3.3.1** 工程图纸应按**专业顺序**编排,应为图纸目录、设计说明、总图、
> 建筑图、结构图、给水排水图、暖通空调图、电气图等编排。
>
> **3.3.2** 各专业的图纸,应按图纸内容的**主次关系、逻辑关系**进行分类,
> 做到有序排列。

§3.3.2 是本蓝图的直接依据——**设计院编号时已经把主次关系编进图号了**,
系统要做的是读出这个既有秩序,而不是另发明一套。

### 1.2 其他相关条款

| 条款 | 内容 | 用在哪一阶段 |
|---|---|---|
| §8.0.1~8.0.7 | 定位轴线(单点长画线、圈径 8~10mm、编号规则、分区编号、附加轴线) | P0 / P1 |
| §11.8.1~11.8.5 | 标高符号(等腰直角三角形)、米制三位小数、`±0.000` | P2 |
| §9 | 除标高及总平面外,尺寸必须以**毫米**为单位 | P2(区分标高与尺寸) |
| §4.0.2 | 图线(单点长画线细=轴线;双点长画线细=假想轮廓线) | P0 |
| §10 图样画法 | 视图配置与剖切表示 | P2 |

## 1.5 ⚠️ 本蓝图 §2 的编号体系**不是通用规律**

`A-01` 轴网定位、`A-10` 完整平面、`S-x-20` 结构平面 —— 这是
**这一家设计院、这一个工程**的编号。换一家就不成立。

§2 之所以保留,是因为它**是归纳的样本、不是判据**。
真正的判据在 `services/drawing_role.py`,**三级级联**:

| 级 | 依据 | 依赖编号吗 | 置信度 |
|---|---|---|---:|
| **1** | **内容特征** —— 轴号圈(§8.0.2)+ 坐标引线(§11.8)/ 标高链 / 轴网带 + 构件数 | **完全不依赖** | 0.92 |
| **2** | **国标术语** —— 平面图/立面图/剖面图/详图/系统图/说明/目录(§3.3.1 + GB/T 50104) | 不依赖(全行业通用) | 0.75 |
| **3** | **编号模式** —— **从本批图纸学出来**,同段角色纯度 ≥80% 且样本 ≥3 才学 | 依赖,但是学的 | 0.55 |

三级都判不出 → `unknown`,**如实标注,绝不猜**。

**内容压过图名**:图名会写错、会残缺(实测 OCR 把 `7-7剖面图` 读成
`8剖面图`),而轴号圈、坐标引线、标高链这些**几何指纹**不会骗人。

### 实测(2309 张,**零编号知识**起步)

| 轮次 | unknown | 覆盖率 |
|---|---:|---:|
| 第 1 轮:仅内容 + 国标术语 | 251 | **89.1%** |
| 第 2 轮:+ 学到的 147 个编号段 | **213** | **90.8%** |

第 1 轮 2058 张由**国标术语**判出 —— 换任何编号体系都成立。
第 2 轮学到的编号段形如 `ZNH-22 → component_source`、`ST-41 → detail`,
**是从这批数据归纳的,不是写死的**;换成 `JZ-SG-01` 也一样学得到。

## 1.6 部分图纸建模(`services/partial_set.py`)

工程上拿到整套竣工图是少数情况。系统若要求「齐了才能建」,大部分时候用不上。

**每一阶段缺失都有降级路径,且不阻断后续阶段;降级结果必须打标记。**

实测四个场景:

| 场景 | 张数 | 世界坐标 | 楼层 | 标高 | 可建模 |
|---|---:|---|---|---|---|
| 全套 | 2309 | full | full | full | ✅ |
| 只有建筑平面图 | 95 | **none** | full | **none** | ✅ |
| 只有结构图 | 319 | **none** | full | full | ✅ |
| 只有详图 | 381 | none | none | none | **❌ 如实说不能建** |

降级时给出的原话(直接展示给用户):

> ⚠ 无坐标基准图(轴号圈 + 坐标标注)——模型只有相对几何,
> **没有世界坐标**,不能与其他单体/测量成果对齐
>
> ⚠ 无立面/剖面图——层高使用**默认值**,非图纸实测值,
> 竖向尺寸不可用于算量或碰撞检查

**这直接解决了当前最大的诚实性问题**:模型 13 层里 10 层是默认标高,
而界面上看不出来。

## 3. 分阶段建模流程

### 阶段总览

```
P0 坐标基准    A-01 轴网定位图            → 世界变换、轴号身份
      ↓
P1 楼层骨架    A-10 完整平面图(一层一张)  → 楼层清单 + 每层轴网
      ↓
P1.5 单体归属  图名部位词 + 人工确认        → 每张图属于哪个单体
      ↓  ← **P2 的前置**:同一个 `F3` 在南区/北区是不同标高
P2 楼层标高    A-20 立面图 / A-30 剖面图  → (单体, 楼层名) ↔ 标高
      ↓  ← 此处才允许创建三维楼层
P3 构件主体    S-x-20/31/32 结构平面      → 柱墙梁板
      ↓
P4 机电        P-/E-/IE- 平面图           → 管线设备
      ↓
P5 细节        A-40~A-71 / S-x-40 详图    → 楼梯坡道节点
      ↓
P6 非几何      目录/说明/表/系统图/通知单  → 档案、拓扑,不进几何
```

### P0 — 坐标基准

| | |
|---|---|
| **输入** | `A-01*` 轴网定位图(实测 3 张);兜底:任何带坐标标注的图 |
| **国标** | §8.0.1~8.0.7 定位轴线;§11.8 标高(坐标标注读数) |
| **产出** | 每图 `drawing_transform`(pt→米)、`axis_intersections` 世界锚点 |
| **判据** | 坐标标注引线末端落在轴线交点上;RANSAC 拟合相似变换(支持反射) |
| **现状** | ✅ 已实现。A-01-02A 实测 RMSE **6.1 毫米**,15 处世界锚点 |
| **缺口** | 全项目仅 **1 张**有世界锚点(需分区号确认);跨图传递未做 |

**为什么第一**:没有世界坐标,所有几何只是页面 pt,拼不到一起。

|---|---|

### P2 — 楼层标高(当前最大缺口)

| | |
|---|---|
| **输入** | `A-20*` 立面图 + `A-30*` 剖面图 |
| **国标** | **§11.8.1** 标高符号=等腰直角三角形;**§11.8.3** 数字注写在符号上/下侧;**§11.8.4** 米制三位小数;**§11.8.5** `±0.000`;**§9** 其余尺寸必须毫米 |
| **产出** | 楼层名↔标高配对表 |
| **判据** | 同一水平行 + 水平相邻 + **只在主标高链上**(标高竖向排成一列) |
| **现状** | ✅ 配对已实现(`level_elevation_pairing`,11 单测)+ **已接进 builder**(`level_elevation_overrides`,31 单测,`_pairing_z_overrides`)|
| **缺口** | **档案层是旧分类,通道暂时喂不到数据**(见下) |

**接线位置**:`section_z.z_overrides` < **`pairing_overrides`** < `manual_overrides`。
按名字匹配优先于按序列对齐(漏读一层不会整条错位),但仍让位于人工录入。

#### P2 落地过程中解决的两个问题

**① 档案是旧分类** —— 楼层名分类的修复做完后,档案里 307 条 `4F` 仍在
`other`、28 条 `大歌剧厅4F` 仍在 `room_name`。

**不需要重抽 OCR**:分类只是对已存 `content` 跑纯函数。建了
`services/archive_reclassify.py` 原地回灌(8 单测)。
实测扫 **102.99 万行,改 12.66 万行**:

| 改动 | 条数 |
|---|---:|
| `room_name → other`(图框会签栏单字噪声) | **125 674** |
| `other → level_name` | 836 |
| `room_name → level_name` | 80 |
| `axis`/`note` → `level_name` | 29 |

**② 我引入的一个真 bug:跨图去重** —— `_pairing_z_overrides` 起初用
`fetch_project_category`,而它内部 `effective_values` 按
`(category, normalized_key)` 做**全项目**去重,`normalized_key` 不含
`drawing_id`。于是全项目 6098 条 elevation 里 `16.200` 只留一条,
配对拿到的是跨图残片。

去重对「项目级信息汇总」是对的,对**几何配对**致命——
配对是**同一张图内**的操作。加了
`drawing_archive.group_rows_by_drawing`(**择优在图内做**,6 单测)。

修完后:配对 **1 条 → 162 条(64 张图)**。

#### P2 的真实结论:一个项目有多套标高体系(数据证实)

配对通了,但 `z_overrides` 覆盖仍是 **0 / 12 层**。
**这不是 bug,是保守判据在起作用。**

按楼层名聚合 162 条配对后的实测分布:

| 层 | n | 众数(极集中) | 南立面图真值 |
|---|---:|---:|---:|
| F2 | 17 | **3.050**(8 次) | — |
| F3 | 20 | **9.350**(8 次) | 大歌剧厅3F **10.300** / 7-7剖面3F **10.800** |
| F4 | 10 | 12.500(5 次) | 大歌剧厅4F **16.100** |
| F5 | 16 | **16.500**(8 次) | 5F(设备层) **26.900** |
| RF | 15 | **25.000**(7 次) | 大歌剧厅屋顶层 **45.500** |

**众数极集中说明数据质量好,问题在归属**:这些裸 `F3`/`F5` 来自结构/机电图,
标的是**不同部位**的楼层。歌剧院南区(大、中歌剧厅)与北区(小歌剧厅)
标高体系完全不同。

另有一条硬证据:**`B1` 同时读出 −5.500 和 +5.500** ——
该标记在某些图上根本不指地下一层。

**⇒ 缺少单体上下文时不能选值。** 现在 0 覆盖,是「宁可留默认值等人工,
也不给一个哪边都不是的值」这条设计在生效。

#### P2 的下一步(链式依赖,尚未做)

配对结果必须带 **building_unit_key** 才能定标高。而单体归属本身
**80.8% 是 `semantic_unassigned`**(见 `CAPABILITY_ASSESSMENT_2026Q3.md` 卡口 B)
——**这是一条链式依赖:单体没定,标高就定不了。**

正确顺序应当是:**P1.5 单体归属 → P2 楼层标高**。
本蓝图原先把单体归属漏掉了,此处补上。

实测真值(A-20-02A 南立面标高链):

| 楼层名 | 标高 | 模型当前 | 差 |
|---|---:|---:|---:|
| 大歌剧厅屋顶层 | 45.500 | 33.9 | −11.6 |
| 6F(设备层) | 36.800 | 24.9 | −11.9 |
| 5F(设备层) | 26.900 | 20.4 | −6.5 |
| 大歌剧厅4F | 16.100 | 15.9 | −0.2 |
| 大歌剧厅3F | 10.300 | 10.5 | +0.2 |

**这是 P2 未接通的直接后果。**

**一个项目有多套标高体系**:大歌剧厅 3F=10.300 vs 7-7 剖面 3F=10.800。
必须按部位分开存,不能混成一张全局表。

## 4. 阶段门禁(建议)

每阶段有明确的**通过条件**,不达标则下游不启动或降级标注:

| 阶段 | 通过条件 | 不通过时 |
|---|---|---|
| P0 | 至少 1 张图求出世界变换且 RMSE < 50mm | 全模型标 `no_world_coords`,只做相对几何 |
| P1 | 楼层清单非空,且每层至少 1 张完整平面图 | 缺层进人工队列 |
| P2 | 楼层标高**来源为图纸**的比例 ≥ 50% | 标 `elevation_default`,前端显式提示"标高为默认值" |
| P3 | 各构件类型的 `*_recognised` 计数 > 0 | 标明是兜底产物(已实现 `slabs_recognised`) |

**当前 P2 会直接不通过**(来源为图纸的只有 2/13 = 15%),
而现在系统不做提示,用户看到的标高像是从图纸读的。

## 7. 设计约束(不可违反)

这几条是系统能服务多个工程的前提,任何后续开发都不得违反:

1. **图号体系不得硬编码。** 判据只能来自:内容特征 → 国标术语 → 学到的模式。
   任何 `if drawing_no.startswith("A-01")` 都是错的。
2. **兜底标准是国标。** 编号可以陌生、图名可以缺失,但只要图上有
   轴号圈(§8.0.2)、标高链(§11.8)、国标图种名(§3.3.1),就能往下走。
3. **降级必须可见。** 默认值不得冒充图纸实测值;
   `partial` / `none` 档位要一路传到界面。
4. **缺失不得阻断。** 缺任一阶段只降级该阶段,不停掉整条链路。
5. **判不出就说判不出。** `unknown` 是合法结论,猜一个不是。
