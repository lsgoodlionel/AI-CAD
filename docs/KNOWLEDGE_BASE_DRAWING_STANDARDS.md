## 2. 产物一：可读可核对的全文（第②层）

`apps/api/data/knowledge/drawing_standards/<key>/book.md`
（正文因版权不进 git，见 `.gitignore`；`meta.json` 进）。

对齐规范库既有的「人机双读三层」（migration 048）：①PDF 原件 ②识别全文 ③结构化条文。

实测质量：

| | 页 | 缺页 | 平均置信 | 字数 |
|---|---|---|---|---|
| 12 本扫描件 | 1359 | **0** | 0.945 ~ 0.985 | 1,012,858 |
| 2 本有文本层 | 492 | 0 | — | 309,739 |

诚实性约束写进了生成器，不是靠自觉：
- frontmatter 记 `extract_method` / `ocr_dpi` / `mean_confidence`；
- **低置信页点名**（`low_confidence_pages`），不埋进平均值；
- **缺页如实标**，不用空串补齐冒充完本；
- 正文最前面一句「未经人工逐字校对，引用前须对照原件」。

一个副产品：图集侧边的竖排章节条（「总则」「平法制图规则」）本是 OCR 噪声源，
被提出来做了**页标题** —— 它是「本页属于哪一章」的直接证据。

## 3. 产物二：符号训练标记数据

`apps/api/data/model3d/dataset/reference/`，**380 条**（253 条无警告）。
详见该目录下的 `DATASHEET.md`。

做法：图例表版式规整（`名称|图例|说明` 或 `序号|符号|说明`），
**同一行就是一对标注**。检表线 → 切单元格 → 认表头 → 逐行配对 → 裁符号图。

三处实测逼出来的判据：
- **先分表块再建网格**：一页常有并排两个表，混在一套网格里会让
  `名 称` 被右表边框劈成两格、表头随之认错（3 条 → 29 条）；
- **旋转方向不猜、试出来**：横排表印在竖开本上转了 90°，两个方向都试，
  **认得出表头的那个才是对的**（218 条来自旋转页）；
- **行带排序**：`金 属` 同一行但 OCR 的 y0 差几像素，按 (y,x) 排会读成 `属金`。

**这份数据的边界必须说清**（DATASHEET §2）：扫描件域 ≠ 生产矢量图纸域，
`docs/PHASE_C_DATASET_SPEC.md` §2.2 本就拒收扫描件。所以它单列为 `reference/` 层，
**不并入 raw/weak_labeled/gold，不参与 C-07 切分**，用途是符号词表、
模板参考、人工标注的对照册 —— 不是「拿去训练检测器就能在生产图上work」。

**282 条 `taxonomy=None` 不是失败**：材料图例是剖面填充图案、
电路元件没有空间实体，它们本就不属于 9 类构件。硬凑一个类别会污染标签。

## 4. 产物三：已生效的识别修正（这才是结果）

### 4.1 平法构件代号表：26 → 72 个，逐条有出处

`core/model3d/component_mark.py`。此前那张表是凭记忆写的，逐页核对图集原件后：

- **新增 22 版代号**：转换柱 `ZHZ`、楼层框架扁梁 `KBL`、托柱转换梁 `TZL`、
  暗梁 `AL`、边框梁 `BKL`、连梁 `LLk`/`LL(JC)`/`LL(JX)`/`LL(DX)`、
  节点核心区 `KBH`、后缀式 `Lg`/`LN`；
- **新增全部楼梯代号**（`AT`~`GT`、`ATa/ATb/ATc/BTb/CTa/CTb/DTb`）——
  此前**一个都没有**，而金标准实测「墙」的最大误检源正是楼梯（31%）；
- **新增全部基础代号**（`DJj/DJz/BJj/BJz`、`TJBp/TJBj`、`JL/JCL`、
  `LPB/ZXB/KZB/BPB`、`CTj/CTz/CTL`、`GZH`）；
- **旧版代号保留**（`KZZ`/`LZ`/`QZ`）—— 实测 16G101 被引用 155 次，
  按旧版绘制的图上就是这么写，删掉会让真实图纸失识；
- 查无出处的（`YZ`/`JLQ`/`YXB`）如实标 `unverified`，不装作有依据。

修掉一个**系统性缺口**：旧实现用 `raw != raw.upper()` 一刀切拒绝含小写的串，
而 `LLk`/`DJj`/`ATa`/`Lg` 是国标规定的写法 —— 这批代号**一个也认不出**。
代号匹配改为按权威表穷举（长代号优先），顺带消掉了「长短代号排序」的隐性依赖。

一个容易记混的细节，靠查原件才对：**独立基础是「阶形 j / 锥形 z」
（`DJj`/`DJz`），条形基础底板才是「阶形 j / 坡形 p」（`TJBj`/`TJBp`）**。

### 4.2 专业闸：挡掉 2368 次假阳性

`parse_component_mark(text, discipline=...)`。加代号时实测发现：

- `LN1`~`LN14` 全库出现 **1144 次，全部在 mep 的配电系统图上** ——
  是照明回路编号，不是「受扭非框架梁」；
- `CT2` 出现在电气「基础接地平面」上，是电流互感器不是 CT 型梯板。

反过来，`AT1`/`BT4`/`DT6` 实测**全部落在 structure 专业的「楼梯 ST-xx 结构详图」**上，
是真的梯板编号。所以判据不是「这些代号可疑」，而是**专业不对就不认**。

全库实测：

| | 次数 |
|---|---|
| 专业闸挡掉的假阳性 | **2368**（其中既有代号 `L` 就占 1069）|
| 新代号净增的真阳性 | **121**（楼梯 102）|

注意这里的意外收获：`L`/`Q`/`XL`/`LL` 这些**既有**代号此前一直在机电图上误收，
是这次加闸才发现并修掉的。

### 4.3 比例表按 GB/T 50001 校订

`services/scale_candidates.py`。旧表含 **`75`** —— GB/T 50001 的常用表与
可用表里**都没有 1:75**，那是凭印象加进去的；同时漏掉 1:1~1:6 的详图档与
1:60/80/600、总图的大比例档。原文在两本教材里逐项一致（互相印证）。

改为**常用/可用两档**，吸附时按标准明文「应优先用表中常用比例」先试常用档。

全库 2142 个 `drawing_transform` 实测：符合国标比例的从 **83.1% → 88.0%**，
新增命中的是 1:600（42 张）、1:3（34）、1:80（13）、1:60（7）等
此前被判「非标准」的合法比例。金标准实测「比例」正确率仅 30%、
是杠杆最大的一项，吸附目标本身不对会把误差固化下来。

## 5. 可复现

```bash
cd apps/api
scripts/knowledge/ocr_all.sh 4                       # ① 扫描件 OCR（缓存在仓库外）
python scripts/knowledge/build_markdown.py --all     # ② 全文 md
python scripts/knowledge/build_symbol_dataset.py --all
python scripts/knowledge/label_symbol_dataset.py     # ③ 符号标注 + 分类
CAD_KNOWLEDGE_DSN=... python scripts/knowledge/ingest_to_db.py --upload   # ④ 入库
```

OCR 缓存在 `~/.cache/cad-knowledge/ocr`（**仓库之外**）：
往 `apps/api/` 里高频追加 jsonl 会让开发用的 `uvicorn --reload` 文件监视器
持续唤醒 —— 实测把 OCR 自己饿到只剩 40% CPU。

## 6. 诚实边界

- 图集正文是**构造详图**而非图例表，本轮的表格法只出了 12 条 ——
  图集的价值主要在文字层，不在符号切图；
- **76 个候选页未出任何数据**（表头认不出）—— 如实记录，未强行出数；
- 全文是 OCR 得到的，**未经人工逐字校对**，不能直接当规范原文引用；
- 新代号的直接增量只有 121 次 —— 这两个工程用到的代号本就不多；
  本轮更大的收益来自顺带发现的既有缺陷（专业闸 2368、比例表 +4.9pp）；
- 资料是**受版权保护的出版物**，派生全文与切图不进版本库、不对外分发。
