## 0. 为什么单独立一个 Phase

Phase H 解决的是「构件如何装配成模型」,前提是**已经知道图纸上有什么**。
但实测发现这个前提不成立——轴网识别长期只有六成召回,轴号完全读不出,
导致 Phase H 的世界坐标定位链路虽然打通,却没有数据可喂。

Phase I 的命题因此是:**把「读图」本身做成按制图标准执行的确定性能力**,
而不是靠几何启发式猜。

**关键约束(用户明确)**:工程上**没有 DWG 是常态**。必须在 PDF 上把识别做到
90% 以上,DWG 路线只作为将来可选增强,不能作为前置条件。

## 1. 口径:真值驱动,不许凭感觉

### 1.1 为什么必须先有真值

立项前的一轮工作里,我在**没有可度量基准**的情况下连下多个错误结论(见 §4)。
每次都"看起来合理",实测全错。**没有标尺,改算法就是盲调。**

### 1.2 真值怎么建

`tests/fixtures/axis_ground_truth.py` —— 人工读图标注,附 8 条自检单测。

方法:把 A0 图按区域渲成放大图,**人眼读轴号并计数**。轴号本身是权威依据——
GB/T 50001 §8.0.2 规定编号注写在轴线端部圆内,一圈对应一条轴线。

**自检不可省**:轴距条数必须等于轴线数 − 1。这条断言就是防止读图时数漏。
实测 A-01-02A 分区 1:24 条竖向轴线 ↔ 23 个轴距值,一致。

### 1.3 度量口径

| | 定义 |
|---|---|
| 分母 | 人工标注的轴线条数(标注不完整的分区**排除**,否则召回率虚高) |
| 分子 | 算法检出且能对上的轴线数 |
| 目标 | **轴线召回率 ≥ 90%** |
| 当前(位置) | **95%**(A-01-02A 全部轴线 103/108) |
| 当前(轴号) | **99/99**,且三个分区各方向条数与真值**逐项相等**(无偏移) |

**错标比漏标更糟**——它会把构件定位到错误的轴线上。

**口径本身被质疑过一次,并因此发现真问题**:「99/99」最初是按**标签集合**算的。
真正问过「每条轴线的名字对不对」才发现分区 2 检出 18 条字母轴线而真值只有 14 条,
4 条附加轴线夹在主序列中间,从第 8 条起 `2-H` 被标成了 `2-J`。
用字形判据剔除附加轴线后,三个分区**各方向条数与真值逐项相等**——
条数逐项相等,序列就不可能偏移,这才是可以下结论的口径。

### 2.4 同心圆(A-01-03A)

### 2.5 轴号圆圈 —— 已 100% 解决

**圈是一个独立 path、恰 4 条贝塞尔弧、包围盒正方形。**

| 图纸 | 全弧方形 path | 直径分布 | 对真值 |
|---|---|---|---|
| A-01-02A | **108** | 28.0pt × 108 | 108/108 ✅ |
| A-01-03A | **107** | 28.0pt × 107 | 107/107 ✅ |
| A-01-04A | 129 | 16.0pt × 126 + 3 离群 | 126/126 ✅ |

- 28.0pt = **9.88mm**,**正落在 §8.0.2 规定的 8~10mm**
- 三张图**只存在 4 弧一种形式**(无 2/6/8 弧变体),放宽弧数只会引噪声
- **图内直径完全均匀,跨图却不同**(28.0 vs 16.0)→ 直径必须按**图内众数**判定,
  绝不能硬编码成全局常量

**此前三次定位失败(同 path 分组 / 包围盒中心聚类 / 拟合圆心聚类)的共同原因是
在跨 path 之间聚类圆弧——而圈本身就是一个完整 path,根本不需要聚类。**
此前测得的「统一 14.0pt」是别的图元,不是轴号圈;由此推出的「约为国标一半」也随之作废。

### 2.5.1 轴号带(§8.0.2 的几何推论)

§8.0.2「编号宜注写在平面图**下方及左侧**」+ §8.0.3「依次注写」⇒ 同族轴线的圈
排成一条**连续的带**,且**带方向与它所标注的轴线方向垂直**。

实测 A-01-02A(容差 = 圈径 × 0.25 = 7pt):

| 带方向 | 成员 | 对应真值 |
|---|---|---|
| 0°(横行) | **24** | 分区 1 数字轴线 24 ✅ |
| 0° | **12** | 分区 2 的 2-1~2-12 ✅ |
| 90°(竖列) | **14** | 分区 2 字母轴线 14 ✅ |
| 42° | **16** | 分区 3 数字轴线 16 ✅ |
| 132° | **11 + 4** | 分区 3 字母轴线 **15** ✅(4 个在边界错台段) |

106/108 圈成带。**带一出,轴线位置由圈直接给出,不必再靠几何阈值猜。**

### 2.5.2 附加轴线用分数式(§8.0.6 确认)

放大到 20× 后确认标签是 `2-1/k`、`2-2/k` —— **分区 2、K 轴之后第 1/第 2 根
附加轴线**,斜线分数式。**此前误读为 `2-1A`(数字+字母注脚)。**

于是轴号语法为:

```
<分区号>-<数字>        主轴线(数字向,§8.0.3 从左至右)
<分区号>-<字母>        主轴线(字母向,从下至上,跳过 I·O·Z)
<分区号>-<n>/<前一轴号>  附加轴线(§8.0.6 分数式)
```

A-01-02A:108 圈 = **100 个主圈**(对应 99 条主轴线,有一条两端各一圈)+ **8 条附加轴线**。
**注**:此前写「99 主轴线 + 9 附加」是错的——那假设一轴一圈,而 §8.0.2 允许两端各注一个。

### 2.6 分区编号解释了「多套轴网」

A-01-02A 有 **4 套轴网**(用户确认,渲图印证):右上旋转 43° 一套、中部正交一套、
下部正交一套、右中小的一套。

轴号形如 `1-1`、`2-1A`、`1-14`、`1-A` —— **正是 GB/T 50001 §8.0.5 的分区编号**
「分区号-该分区轴线号」。这解释了 4 套轴网如何共存:靠 `1-`/`2-` 前缀区分。

**同时纠正**:此前把 `1-1` 当作「附加轴号」处理是错的。按 §8.0.6,附加轴线用
**分数形式**(分母=前一轴线号,分子=附加号),1 号/A 号之前用 `01`/`0A`。

### 2.7 坐标标注

十余处 `X=-5922.086 / Y=-110.362` 形式的标注,**全部位于轮廓转角上**。
形式(用户描述 + 渲图印证):交叉点起 → 拉一根折线(斜段 + 水平段)→
水平段上方/下方两行写 `X=` / `Y=`,数值**可正可负**。

已读出 A-01-02A 的 6 处(见真值 fixture)。

## 5. 三个真 bug(已修,均由真值暴露)

### 5.1 `_normal_offset` 根本不是法向

用 `(sinθ, cosθ)` 当法向,与方向向量 `(cosθ, sinθ)` 的点积是 **`sin2θ`**,
**只在 0°/90° 才为 0**。于是旋转轴线的"法向偏移"几乎沿着线本身,同一条线上的
碎段被算出天差地别的偏移,永远聚不成一条。

正交方向侥幸正确,**把问题掩盖了很久**。已改为 `(-sinθ, cosθ)`,并加单测钉住:
同一条 45° 线上不同段的偏移必须相同。

同一 bug 也存在于 `services/axis_geometry.axis_offset`,已一并修正。

### 5.2 方向投票门槛把虚线轴线整体排除

`MIN_LENGTH_FOR_DIRECTION_PT = 30`,而**点划线的划只有 10.5pt** ——
虚线轴线对主方向投票**毫无贡献**。

真图上能测出 0°/90°,靠的是图框与构件的长实线恰好同方向;**旋转轴网没有长实线
撑着,方向就永远找不到**。这才是它缺失的主因,不只是 §5.1 的法向算错。

已降到 2.0pt。既然投票按长度加权,极短段权重自然极小,不必靠长度门槛去噪。

### 5.3 覆盖率判据方向反了

按「覆盖率越高越像轴线」筛,竖向检出 **187 条**(真值 36)——因为
**覆盖率 1.0 恰恰是实线**(构件轮廓/图框),而轴线是点划线、覆盖率 0.3~0.9。

改为**按线型判**(只留单点长画线),一步到位:竖向 30/36。
这是「按国标读」替代「调阈值」的典型收益。

与真值(39 竖 + 29 横)完全吻合;**31 条斜轴按设计跳过**——
scene 轴网是「一维位置 + 标签」,表达不了旋转分区,硬投影会在模型里指向别处。

**闭环验证**(确认分区号 → 重跑 → 锚点与 scene 同步更新):

    确认前  zones_pending_label=3  锚点 7   scene 轴号重复
    确认后  zones_pending_label=0  锚点 8   scene `1-1…2-15` / `1-A…2-P` 无重复

**途中修掉四个真问题**:

1. **魔数**「主带成员数 ≥ 8」是从验证脚本带进服务的——小图纸的分区只有五六条
   轴线会被整个漏掉。改用「**有没有配上垂直的对**」作判据,配上的成区,
   落单的再按二维范围吸附。真图结果无退化。
2. **未确认分区号时锚点会串图**:锚点身份是轴号对,分区号缺失时轴号退化成裸标签,
   两个分区的 `1 × A` 撞成同一身份被去重——实测锚点从 8 掉到 7。
   改为**只为已确认分区写锚点**。这让人工确认真正承重,而不是走过场。
   同一条规则也用在 scene 轴号上:未确认分区的标签有歧义,而 `_merge_axes`
   会拿带标签的去升级无标签的,歧义标签会污染别的轴线。
3. **可选参数位置传参插错位**:给 `build_floor_elements` 加参数时插在了
   `archive_text_by_drawing` 之前,而调用点是位置传参——会把档案文字当成识别轴号。
   改回原顺序并**一律用关键字传**。
4. **失败处理器自己会抛**:`_mark_failed` 用 `asyncio.run`,在已有事件循环时
   抛 RuntimeError **把原始错误盖掉**,排查时只看得到二次错误。已加保护。

## 9. 方法论(这一轮最硬的收获)

1. **先建真值,再改算法。** 没有尺子时我连下多个错误结论,有了尺子后
   两次改动立刻被证伪(分区聚类量出「零改进」、覆盖率主筛量出「187/36 过检」)。
   **证伪比证实值钱。**
2. **渲图看比几何盲猜有效得多。** 一张图看下来,4 套轴网、分区编号、
   坐标标注位置、轴距数字全部印证。这该是第一步而不是最后一步。
3. **按标准读优于调阈值。** 线型判据一上,竖向从 44% 跳到 83%;
   而此前调了三轮阈值都在原地打转,还一度反向(覆盖率越高越像轴线)。
4. **子结构的门槛要相对同类,不能相对全图。** 三个 bug 里两个源于此。
5. **属性读不到不等于信息不存在。** `dashes`/`width` 全为 0,但节奏还在。
6. **补真值的第一件事是重算历史数字。** 分母一补全,上一版的 92% 立刻变成 71%
   ——好消息是同一次补全也直接指出了正解(圈数 108 与轴线数严丝合缝对上)。
7. **最小二乘对粗差没有免疫力。** 19% 粗差就能让残差失去判别力(9~183m 无分界),
   此时「剔除最大残差」这类常规手段根本触发不了。有粗差就上 RANSAC,
   而且**穷举而非随机采样**——同一输入必须给同一答案,否则无法回归测试。
8. **同一个工具在不同尺度上结论相反。** RapidOCR 读轴号 1/24(发丝笔画小字),
   读坐标 16/16 置信 0.96~1.00(字大一个量级)。「OCR 不行」是个太粗的结论。
9. **集合覆盖 ≠ 逐条正确。** 「99/99 命中」是按标签集合算的;真正问过
   「每条轴线的名字对不对」才发现分区 2 从第 8 条起整体偏移。
   **度量口径本身也要被质疑一次。**
10. **一个判据在单张图内就可能自相矛盾。** 「间距小 = 附加轴线」在分区 2 成立,
   在分区 1 却会误杀主轴线——同一张图,区间完全重叠。判据要在**全部样本**上验,
   不能只在它成立的那部分上验。
11. **干净的分界要先确认不是判据的盲区。** 角度窗 50~85° 时字母斜画测出 0.063,
   分界看着比真实情况还漂亮——那是 K、N 落在窗外**没被测到**。
   把窗口放宽、让反例真实出现,分界仍然成立,结论才立得住。
12. **「结果为空」要区分是没数据还是被正确拒绝。** placements 长期为 0,
   一度以为是缺锚点;补上锚点后仍是 0,查下去才发现是残差 105m 触发了
   suspect 保护——保护是对的,缺的是**反射支持**。
13. **把结构当判据,而不是把阈值当判据。** 圈锚定之所以一步到 95% 且近零误检,
   是因为「一个圈 = 一条轴线」「圈成带、带⊥轴线」都是**国标条款**,
   不是调出来的数。凡是要靠调阈值才成立的判据,都该先怀疑找错了判据。
