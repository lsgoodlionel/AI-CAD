## 0. 目标与「准确」的正确定义(必须先对齐)

**目标**:通过图纸各引擎识别 + 大模型能力,逐张图装配出一个**结构正确、竖向真实、每个构件
与来源图纸一一对应、可人工核对**的三维模型。

**关于「准确」的诚实定义(决定成败的认知前提)**:
输入里有大量无图层、取不到矢量文字的扫描 PDF(歌剧院 2309 图 100% 如此),信息本身有损。
因此「全自动一次到位的准确」在物理上不可得。**本方案的准确性来自两个机制,而非幻想的完美自动化**:

1. **多观测相互校验 + 工程约束收敛**:同一构件在多张图上的多次识别相互印证,离群被约束剔除;
2. **人审在环单调收敛**:人在图纸上核对确认,把 auto 构件逐步转为 confirmed,准确率单调上升。

> 一句话:**我们不追求「自动生成完美模型」,追求「结构正确 + 每个构件可追溯到具体图纸内容 +
> 人一核就准,且越核越准」**。这恰是你要的「可人工核对、构件与图纸一一对应」。

## 1. 关键发现:硬核配准能力已存在,缺的是「身份 + 沉淀 + 核对」

核实代码后确认,以下**难做的部分已经有真实实现**(不是从零造):

| 已有资产(真实接口) | 能力 | 在新方案中的角色 |
|---------------------|------|------------------|
| `grid_anchor_extractor.extract_grid_anchors(geom) -> GridSystem` | 抽轴线+轴号作跨视图锚点 | **关联主键**(见 §3) |
| `cross_view_registration.register_views(...)` + `_build_axis_map()` | **把各视图轴号统一到参考帧** + z 装配 + 冲突清单 + provenance | **空间配准骨干** |
| `section_level_extractor.extract_section_levels` + `filter_main_sequence`(RANSAC-lite) | 剖面标高序列(带鲁棒筛选) | **Z 真值来源** |
| `section_z_recovery.recover_section_z(...)` | 剖面标高→层高覆盖 + 匹配单体,点亮 `cross_view_match` gate | **竖向定位** |
| `drawing_transform`(`pt_to_meter`/`fetch_project_transforms`) | 每图 pt→米(幂等落库) | **米坐标 + 回投图纸** |
| `circle_detector` / `element_recognizer` | 桩/柱/墙/梁/板识别 | **观测源(证据)** |

**真正缺失的三样**(本方案补齐):
1. **构件身份(identity)与持久化**:把上述引擎的碎片产物沉淀成有唯一 id、带多观测、带
   provenance 的 `ComponentInstance`,而不是拍平进 `floors[].elements[]`。
2. **数据关联(association)**:用**已有的轴号统一映射**把多视图观测绑到同一构件(而非靠脆弱的
   米坐标)。
3. **人审核对闭环**:构件回投到每张源图叠加标记,人确认/否定/改类/补漏 → 写回 + 训练飞轮。

## 1.5 数据流总览与路线决策

**数据流(从图纸到可核对模型)**:

```
 图纸(DXF/DWG/PDF)
   │  各引擎(element_recognizer / circle_detector / spotting / OCR / VLM)
   ▼
 [L1 证据]  每次识别 = 一条 Observation(drawing_id + view + engine + archive_ref + 置信)
   │  轴号统一(cross_view_registration._build_axis_map)+ pt→米(drawing_transform)
   ▼
 [L2 关联]  按「轴网格 + 类型」把多视图观测绑到同一构件(§3)
   │  剖面标高(section_z_recovery)定 Z + 构件表(大模型)定守恒目标
   ▼
 [L3 实体]  ComponentInstance(唯一 id + observations[] + z_source + review_state)
   │  工程约束收敛(落轴网 / 跨层连续 / 数量对齐)+ 冲突入人审
   ▼
 [L4 核对]  回投每张源图叠加标记 → 人 确认/否定/改类/补漏 → 写 verified + COCO 飞轮
   │  instances_to_scene()
   ▼
 [L5 模型]  scene(保留构件身份)→ 点击单构件 → 证据链(接 Phase G/G4)
```

**为什么是「实体中心装配」,而非另外两条路**:

| 路线 | 能到的上限 | 代价 | 判断 |
|------|-----------|------|------|
| 继续补强现范式(修引擎/加 OCR/调参) | 更好看的体量,但构件不准、不可靠追溯 | 低,但撞方法论天花板,边际递减 | ❌ 到不了「准确+可追溯」 |
| 全部推翻重写 | 理论最高 | 极高,丢弃已有配准/档案/渲染/人审资产 | ❌ 没必要 |
| **实体中心装配(本方案)** | 逼近「准确+每构件可追溯」 | 中,复用现有配准引擎,只加身份+人审层 | ✅ 采纳 |

**决定性理由**:碎片堆叠范式的误差是「噪声之和」(图越多越糊);实体中心 + 多观测校验 +
人审收敛,误差是「相互印证后收敛」(图越多越准)。而 §1 已证实配准硬骨头是现成的,补强成本可控。

## 2. 核心数据模型(migration 033)

> 注:蓝图初稿写「032」,实际 032 已被 `archive_scan_summary` 占用,顺延为 **033**
> (`migrations/033_component_instances.sql`,已应用)。instance 主键实现为 UUID(比 TEXT
> 稳健、合项目约定),语义 id 存 `semantic_key` 列 + 唯一索引。

```sql
CREATE TABLE component_instances (
    id             TEXT PRIMARY KEY,           -- 稳定语义 id,如 "col:unitA:C-3"
    project_id     UUID NOT NULL,
    model_version  INT  NOT NULL,
    building_key   TEXT NOT NULL,
    type           TEXT NOT NULL,              -- column|wall|beam|slab|pile|door|window|pipe|equipment
    grid_ref       TEXT,                       -- 轴网定位 "C-3"(关联主键,来自统一轴号)
    outline_m      JSONB,                      -- 配准后米坐标轮廓
    z_bottom_m     REAL,                       -- 真实标高;NULL=未知,严禁默认套
    z_top_m        REAL,
    z_source       TEXT,                       -- section|elevation|story_default|null(provenance)
    section_json   JSONB,                      -- 截面 {w,h,d},可来自构件表
    type_label     TEXT,
    review_state   TEXT NOT NULL DEFAULT 'auto', -- auto|confirmed|rejected|conflict
    confidence     REAL NOT NULL DEFAULT 0,
    reviewed_by    UUID, reviewed_at TIMESTAMPTZ,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE component_observations (
    id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    instance_id   TEXT NOT NULL REFERENCES component_instances(id) ON DELETE CASCADE,
    drawing_id    UUID NOT NULL,
    view_type     TEXT,                        -- plan|section|elevation|detail
    engine        TEXT NOT NULL,               -- rule|circle|yolo|spotting|ocr|vlm|human
    grid_cell     TEXT,                        -- 该观测落在的轴网格 "C-3"
    local_coord   JSONB,                       -- 该图页面坐标(pt)
    world_coord   JSONB,                       -- pt_to_meter 后(可空:无 transform 时)
    archive_ref   UUID,                        -- → drawing_extracted_info.id,溯到「具体内容」
    confidence    REAL NOT NULL DEFAULT 0,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_ci_proj_ver ON component_instances(project_id, model_version);
CREATE INDEX idx_obs_instance ON component_observations(instance_id);
CREATE INDEX idx_obs_drawing  ON component_observations(drawing_id);
```

**「构件↔图纸一一对应」就落在 `component_observations`**:一个构件的每条观测精确记录
「哪张图(drawing_id)、哪个视图(view_type)、哪个引擎、哪条档案内容(archive_ref)、
落在哪个轴网格(grid_cell)」。点击构件即可列出它的全部来源图纸与每张图的具体贡献内容。

## 3. 装配算法:以「统一轴号」为主键的数据关联(方案核心)

**关键洞察**:`drawing_transform` 仅覆盖 705/2309 图,靠米坐标关联会因大量图无变换而失败。
而 `cross_view_registration._build_axis_map()` **已经把各视图轴号统一到参考帧**——轴号(C-3)
比米坐标鲁棒得多。**所以关联主键用「轴网格 + 类型」,米坐标为辅校验。**

```python
def assemble(project_id, model_version) -> list[ComponentInstance]:
    # 0) 复用既有:统一轴号映射 + 标高表(硬核配准已有)
    reg = cross_view_registration.register_views(planes, sections, elevations)  # 已存在
    axis_map = reg.axis_map          # 各图轴号 → 参考帧
    levels   = reg.levels            # 带 provenance 的统一标高表
    transforms = fetch_project_transforms(db, project_id)  # 已存在

    # 1) 各引擎输出 → Observation(不改引擎内部,只做适配)
    obs = []
    for d in drawings_in_reading_order(project_id):   # §5 阅图顺序
        for det in run_engines(d):                    # element_recognizer/circle_detector/...
            obs.append(Observation(
                drawing_id=d.id, view_type=d.view_type, engine=det.engine,
                grid_cell=locate_in_grid(det, axis_map[d.id]),      # 落到统一轴网格
                world_coord=pt_to_meter(det.xy, transforms.get(d.id)),  # 有 transform 才算
                archive_ref=det.archive_ref, confidence=det.conf))

    # 2) 关联:轴网格+类型 为主键,米坐标为辅(track association)
    instances = {}
    for o in sorted(obs, key=lambda o: -o.confidence):
        key = association_key(o)          # (building, type, grid_cell) 优先;缺格→米坐标聚类
        if key in instances and gate_ok(instances[key], o):
            instances[key].observations.append(o)      # 累积证据,置信升
        else:
            instances[key] = ComponentInstance.from_obs(o, grid_ref=o.grid_cell)

    # 3) 聚合估计
    for inst in instances.values():
        inst.outline_m = fuse_outline(inst.observations)
        inst.z_bottom_m, inst.z_top_m, inst.z_source = recover_z(inst, levels)  # 剖面优先,无则 NULL
        inst.type = vote_type(inst.observations)
        inst.confidence = f(len(inst.observations), consistency(inst))

    # 4) 工程约束收敛
    snap_to_grid(instances, axis_map)              # 柱落轴网交点
    enforce_vertical_continuity(instances)         # 跨层柱/桩连续
    reconcile_with_bom(instances, bom_from_llm)    # 数量/规格对齐构件表(§4 大模型)
    for inst in instances.values():
        if has_conflict(inst) or inst.confidence < TH:
            inst.review_state = "conflict"          # 入人审队列(§6)
    return list(instances.values())
```

**关联降级阶梯(`association_key` 的鲁棒性来源)**:

1. **首选:轴网格 + 类型** —— `(building_key, type, grid_cell)`。轴号经 `_build_axis_map`
   跨视图统一,最鲁棒,不依赖 transform 覆盖率。
2. **次选:米坐标聚类** —— 该图有 `drawing_transform` 但无轴网格命中时,用 world_coord
   近邻聚类关联(阈值门控)。
3. **兜底:标 `unregistered`** —— 既无轴网格又无 transform 的观测,**不注入世界坐标**,
   单独入人审补基准(呼应 G9 止血:绝不硬塞造错位)。

**防错**:`gate_ok` 要求「轴网格一致 + 类型一致 +(若都有 transform)米距 < 阈值」;任一冲突
→ **新建实体而非强并**(宁分裂待人审合并,不错并造假构件)。

## 5. 阅图顺序作为装配编排原则(G5)

人读整套图的顺序,正是让装配「先立约束、再定平面、后校竖向」的正确序:

1. **先读全局约束**:目录 → 总说明 → 构件表(→ 大模型职责 A 产出 `bom` 与标高表)。
2. **按专业**:建筑 → 结构 → 机电 → 幕墙 → 装修(先骨架后系统外围)。
3. **按竖向自下而上**:桩基 → 围护 → 地下 → 地上(与施工一致,先锚定基底基准面)。
4. **单专业内**:平面(定 XY/轴网)→ 剖面(定 Z)→ 详图(补截面/细部)。

`drawings_in_reading_order()` 用 `drawing_view_classifier` + `drawing_filename_parser` 排序;
先处理的图为后处理的图提供约束(标高表/轴网/基准),使误差收敛而非累积。

## 6. 人审核对闭环 —— 「构件↔图纸一一对应」的可核对界面(重中之重)

这是你最看重的部分:**人能核对模型与图纸的对应关系,且核对驱动模型变准。**

```
装配出实体 → 用 drawing_transform 逆变换回投到「每一张源图」→ 图纸预览叠加彩色标记
      柱=蓝 墙=红 梁=橙 板=灰 桩=青 标高=绿点 轴网=虚线 门窗=黄
            │  (每个标记 = 一个 ComponentInstance 在这张图上的 observation)
            ▼
   人在图上逐个核对:
     ✓ 确认      → review_state=confirmed;写 archive verified;沉淀正样本
     ✗ 否定      → review_state=rejected;从模型移除;沉淀负样本
     ⇄ 改类/改轴  → 更正 type/grid_ref;写 verified
     ＋ 补框      → 新建 human 观测→新构件;沉淀正样本(COCO)
            │
            ├─(a) 即时增量重建该构件 → 模型页立刻反映
            └─(b) COCO 金标签 → 训练识别器(喂 C-09)→ 下批图更准(飞轮)
```

- **双向核对**:①在**图纸**上看「这张图的构件标记对不对」;②在**模型**上点构件看「它来自哪些图的哪条内容」(接 Phase G 追溯 + G4 明细)。二者共用同一 `observations` 数据。
- **复用**:C-16 `DrawingAnnotationQueue`(符号级)升级为**构件级 + 全类型 + 回投叠加**;
  写回复用 `drawing_archive.persist_verify`。
- **收敛度量**:confirmed 占比单调↑;人审点击/分钟↓(飞轮见效)。

## 9.5 真实度提升(H8,本地工程实测驱动)

对上海大歌剧院实测模型做真实度诊断,发现并修复两个硬伤:

### H8-1 柱截面模数化对齐(真实度,3D 可见)✅

**诊断(实测)**:柱宽 **46.5% 偏离 50mm 模数超 10mm**,出现 **124 种**不同柱宽

**方案**:`services/component_dimension.py` — 截面吸附到标准截面/50mm 模数,
**只吸附小偏差**(≤30mm 容差),超容差不动(保留真实异形/误检原貌,不掩盖)。

| 指标 | 修复前 | 修复后 |
|------|-------|-------|
| 柱宽偏离 50mm 模数 >10mm | 46.5% | **0.2%** |
| 偏差 p50 / p90 | 9.0 / 21.0 mm | **0.0 / 0.0 mm** |
| 不同柱宽种类 | 124 种 | **32 种** |

**双路生效**:① `model_builder._attach_floor_elements` 末尾 → 后续重建自动生效
(3D 渲染直接读 scene.elements);② `component_pipeline` 装配 instances。
**仅柱/桩**:板轮廓(=建筑外形)、墙梁 path(=构件走向)不动,避免破坏真实形状。
真实 scene 已写回,3D 立即受益(5674/5704 柱)。

### H8-2 竖向真实率口径修正(诚实指标)✅

**诊断**:H7 报「竖向真实率 1.0」是**虚高**——`apply_floor_z` 给所有层记
`floor_elevation`,而 `scene.quality.story_tables` 显示大歌剧院 **north/south 全部
`height_source=default`**(系统默认套 4.2/4.5,`DEFAULT_BASEMENT_HEIGHT_M`),标高其实是猜的。

**方案**:`story_z_sources(scene)` 从 story_tables 取**真实 provenance**;

**结果**:竖向真实率 **100%(虚高)→ 0.0%(诚实)** —— 如实暴露「该模型楼层标高几乎全

口径取**所属单体**(保守低报),而非取最真实(会把 default 说成真实,虚高到 100%)。

## 9.6 三方向攻坚(H9,实测驱动)

### H9-1 平面图标注恢复楼层标高(补剖面覆盖不足)⏳ 候选待人审

|------|--------------|------|
| 尺寸链相邻标注中心距推比例尺 | **3.6%**(83/704 有结论) | 假设在真实 OCR 数据上不成立;提高票数门槛只降覆盖不提精度(3→80 票准确率 3.6%→0%)。**模块已删除**,不留误导代码 |

### 比问题本身更重要的发现:**瓶颈性质被误判**

用"是否符合标准比例尺"反查现有变换质量:
- 705 个已有变换**平均 confidence 仅 0.007**;
- **仅 46.1% 符合标准比例尺(±5%)**,53.3% 非标准 → **建议复核**。

> **结论**:这不是"覆盖率不足"的问题,而是**质量问题**。我此前把这批变换当"真值"评估
> 新算法,本身就不可靠;而用不准的算法盲目提覆盖只会更糟——**错变换让构件位置全错,
> 比没有变换更坏**(与 G9 止血同一原则)。

### 可执行路径(采纳):比例尺候选 + 人审在环

`services/scale_candidates.py` —— 不自动落库,产出**可解释的高置信候选**:
- 从 OCR 文本提 `1:N`(施工图上**明确写出**的信息),按标准比例尺吸附;
- 命中标准值即**精确换算**:`scale = N × 25.4/72 / 1000`(1:100 → 0.03528,与实测真值一致);
- 给票数/占比/是否标准,人确认后落**精确**变换。

**实测可执行性(1604 张无变换的图)**:
- **1310 张有比例尺候选**;其中 **1205 张(92%)首选为标准比例尺**(换算精确);

**为何这条路对**:把"不可靠的自动猜测"换成"高置信候选 + 极低成本人审",与 Phase H
人审在环范式一致;人确认一次即得精确变换,并一次性解锁回投核对与金标签飞轮。

## 9.13 根治轴号识别的尝试(H16)——实质改善但**未达可用**

**方法**(基于建筑制图标准):轴线端部画**圆圈**(直径 8–10mm),圈内写轴号。
故正确路径是「先找圈、再读圈内字」,而非把全图数字当轴号。

`core/model3d/axis_circle_detector.py`(11 单测)判别链:
1. **半径众数簇** —— 同图轴号圈大小统一,柱/桩截面圆大小各异;
2. **圆去重** —— Hough 对同一圈重复检出(实测同一「2」检出 5 次);
3. **裁剪放大 ×3 + 置信 ≥0.75** —— 小图块 OCR 易误识;
4. **圈内文字形态** —— 1–2 位数字/字母;
5. **序列单调性** —— 数字轴号按位置排序应递增(可整图否决)。

**实测(南区地下一层结构平面总图,7021×4967)**:

| 方案 | 有效轴号 | 逆序率 | 判定 |
|------|---------|-------|------|
| 现有档案数据(全图 OCR 文本筛) | — | **0.60** | 比随机(0.5)还差 |
| 圈检测 + 圈内 OCR | 31 | 0.203 | 不可信 |
| + 圆去重 | 32 | 0.203 | 不可信 |
| + 置信过滤 + 放大 ×3 | 19 | **0.209** | 不可信(门槛 0.15)|
| 300dpi | 3 | — | 有效轴号太少 |

**诚实结论**:方法论正确——逆序率从 **0.60 → 0.21** 是实质改善,证明「圈内取号」
方向对。但**仍未达可用标准**:大量圈被误识为同一字符(如反复出现的「2」),
根本瓶颈是**通用 OCR 在小图块单字符上的识别能力**,不是再调几个参数能跨过的。

**本模块仍保留并有价值**:`monotonic_violation_rate` 可**整图否决**不可信的轴号识别,
阻止坏数据污染配准与装配(与既有 `align_by_shared_axes` / `filter_real_axes` 同一防线)。

**真正跨过需要**(超出参数调优):专用字符识别模型(而非通用 OCR),或矢量图纸
(有图层的 DXF 可直接读文字)。本项目 100% 扫描 PDF,存在物理上限。

## 9.14 人工标定轴线基准(H17)——绕开 OCR 瓶颈的通道

**用户提出的方案**:人工指定几张初始轴线作为**参考系**,在此基础上再做系统大范围识别。
标定时机不限:上传图纸时 / 建模过程中 / 建模完毕的修正阶段。

**为什么这是对的**:§9.12/§9.13 已证明自动轴号识别撞到物理上限
(档案数据位置序与数值序仅 **0.3%** 一致;轴号圈+圈内 OCR 后逆序率 0.60→**0.21**,
仍未过 0.15 门槛)。**少量人工基准即可绕开**——不必等 OCR 变好。

### 实现

- **migration 034** `manual_axis_references`:两点定一条轴线,存**归一化页面坐标**
  (同除 page_h,与构件回投同口径,与渲染分辨率无关);可选
  `spacing_to_prev_mm` 记录与上一条同向轴线的**实际轴距**。
- `services/manual_axis.py`(8 单测):
  - `axis_position` —— 取轴线位置,**标歪的线(超 5% 容差)判无效**;
  - `scale_from_spacing` —— **由实际轴距直接反算比例尺**
    (`scale = 轴距(m) / 图上距离(pt)`),多组样本取中位数 + 离散度;
    **比读图上 `1:N` 文字更可靠**——量的就是图↔实物的比值;
  - `to_scene_axes` —— 人工轴线 → scene 轴网(米坐标,与构件同系)。
- **端点**:列出 / 标定(幂等覆盖)/ 删除 / **按轴距反算比例尺并落变换**(置信 1.0)。
- **建模接入**:人工基准**优先于**自动识别的轴网;且
  `filter_scene_axes` 对 `axes_source=manual` **放行**——自动合理性校验是为挡住
  自动识别的错轴网,不该推翻人的判断。
- **前端** `components/AxisCalibrator.tsx`:图上点两点画轴线 + 填轴号/轴距,
  已标轴线红色叠加显示,支持缩放平移;入口挂在**图纸预览弹窗**(全站可达,
  对应「上传时/过程中/建模后」任意时机)。

### 标定的两种形式(H17.2)

按实际读图习惯,标定不该逼人手描端点。落地两种:

| 形式 | 操作 | 适用 |
|------|------|------|
| **单条标定** | 填轴号 → **照着图纸内容直接点中那条线**(吸附到候选轴线) | 只需少量锚点;或补标个别轴线 |
| **批量标定** | 连续点选多条线 → 只填**起始轴号 + 终止轴号 + 命名方向**(从左到右/从右到左/从上到下/从下到上)→ 系统自动按序派号 | 一次把一整排轴线标完 |

支撑这两种形式的两块新实现:

- `core/model3d/axis_line_detector.py`(8 单测)—— **候选轴线抽取**,让人「点线」而非「描线」:
  栅格化 → Canny + HoughLinesP → **判横平竖直 → 点划线碎段按位置聚合并回一条(包络取跨度)
  → 按跨度筛掉标注线/引出线**。歌剧院结构平面实测每图 **34~51 条候选**(竖 15~27 / 横 19~24)。
  抽不出候选时**降级为手描两点**,不阻断标定。
- `services/axis_label_sequence.py`(14 单测)—— **轴号序列与方向排序**:
  数字号顺推;字母号**按制图标准跳过 I、O、Z**,用尽后 AA、BB;
  命名方向决定排序(归一化 y 向下为正,故「从上到下」= y 升序)。
  **填了终止轴号则校验条数**——选中 4 条却填「1~9」直接 400 报错
  (`选中 4 条线对应轴号 1~4,与填写的终止轴号 9 不符`)。**错配轴号比不标更糟,宁可让人重选。**

端到端实测(歌剧院「北区三层墙柱平面图」):候选 34 条 → 取 4 条竖线批量标定
「起 1 止 4 · 从左到右」→ `{"saved":4,"labels":["1","2","3","4"]}`,读回位置有序;
条数不符用例如实 400 报错。**测试数据已清理**。

### 入口在哪(H17.3)

标定入口原本只藏在「工程信息 → 明细某一行 → 预览弹窗 → 底部按钮」,**找不到**。补齐三处显式入口:

1. **工程信息页「轴线标定基准」面板**(`AxisCalibrationPanel.tsx`,锚点 `#axis-calibration`)
   —— 直接列出「哪些图该标、标了几条、状态」,一键「去标定」。
   `services/axis_calibration_status.py`(7 单测)供数:**未标定的平面图排最前**
   (轴网画在平面图上,先立平面图参考系);状态分 未标定 / 部分标定(<4 条,不足以定间距)/ 已建参考系。
2. **人审统一工作台**新增待办「标定轴线基准」(high),与比例尺确认并列——工作台本就是为解决入口散落而建。
3. **图纸列表页预览弹窗**补传 `projectId`,预览里即可直接标定。

实测(歌剧院):待标定平面图 **1035 张**,工作台已列为最高优先级待办。

### 价值

| 维度 | 自动路径 | 人工基准 |
|------|---------|---------|
| 轴号可信度 | 逆序率 0.21(不可用) | 人核过,直接可信 |
| 比例尺 | 读文字 `1:N`(93% 命中标准值) | **按实际轴距反算**(直接量比值) |
| 覆盖成本 | 全自动但不可用 | 每图几条线,**少量投入换可靠基准** |

## 9.15 图框「专业」栏 → 全面修正图纸专业(H18)

**问题**(用户实测点名):专业靠文件名/标题关键词猜,大量错判——
`67 舞台深坑区域地质剖面展开图` 判成 general(实为**基坑围护**)、
`64 基坑东侧地质剖面展开图` 判成 structure(实为**基坑围护**)、
`IP-41-30 五层卫生间详图`/`IP-41-32 地下一层厨房排水详图` 判成 general(实为**给排水**)。
而**图框里有「专业」这一栏**,是设计单位填写的权威值。

**关键认识:不必重新 OCR。** 图框文字早已在档案层(`drawing_extracted_info`,带 bbox),
按版式规律取值即可——**「专业」标签右侧同一行的第一个非标签文本**就是专业值。

`services/title_block_discipline.py`(17 单测)三道关:

1. **空间定位** —— 标签右侧、同一行(容差按标签自身高度的 1.2 倍),取最近的一个;
2. **跳过邻栏标签** —— 图框里 `DISCIPLINE`/`图号`/`阶段` 紧挨着专业栏,直接取最近文本会取到它们。
   更麻烦的是 **OCR 把 `DISCIPLINE` 糊成 `DISILIE`/`DISCIPLIME`/`DISCIRLIE`/`BISCIPLIE`**,
   穷举写不完 → 改按「**专业值必含汉字**」一刀切;
3. **封闭词表校验** —— 图框专业是有限词汇(建筑/结构/给排水/暖通/电气/基坑围护/幕墙/精装…),
   词表外一律判未知。**宁可留空让其他信号兜底,也不写入错值**——错专业会误导筛选与规则引擎选型。

**双层存储**(migration 035):`discipline_label` 存图框实读专业(给排水/基坑围护/电气…)供显示与筛选;
`discipline` 保持粗粒度枚举由 label 映射修正——规则引擎/建模按粗粒度选型
(`structure.yaml`/`mep.yaml`),直接写「给排水」会破坏选型。
`COARSE_MAP` 取值受 `drawings.discipline` 的 CHECK 约束限制
(architecture/structure/mep/decoration/general),已加断言防越界写库失败。

**实测结果**(歌剧院 2311 图,已全量写入):

| | |
|---|---|
| 读到专业 | **2171 / 2308 = 94%** |
| 分布 | 电气 1035 · 建筑 485 · 结构 353 · 给排水 226 · **基坑围护 72** |
| 用户点名的 5 张 | **5/5 全部修正正确** |
| 未读到的 140 张 | 主要是图纸目录类(图框版式不同/无专业栏),前端显式标注「(未读到图框)」而非悄悄归入某大类 |

**闭环**:抽取流程(`tasks/drawing_info_extract.py`)内接入,**新导入的图纸抽取完即定专业**;
`POST /projects/{id}/discipline-backfill` 可随时全量重跑(`dry_run=true` 只统计不写)。

**前端**:图纸列表专业列显示实读专业;**常驻专业筛选栏**一点即筛,带每专业张数。

## 9.16 按图纸目录组织整套图(H19)

**需求**:① 图纸默认排序是目录,后续内容按目录顺序;② 可展开一棵目录树,点图名直跳该图。

**目录从哪来**:图纸目录本身就是几张图(实测 **69 张**),其表格已被 OCR 进档案层。
按表头 `DRAWING NAME` 定位图名列 → 取其下方按 y 排序的条目 = 目录顺序
(`services/drawing_directory.py`,18 单测)。两个必须处理的细节:

- **续行碎片要拼回本行** —— 「消火栓系统原理图」和「(二)」是两个 OCR token,
  按 y 容差 6pt 归行、按 x 拼接,否则「(二)」会变成一条独立的假条目;
- **匹配要用后缀而非全等** —— 库里图名带前缀(`给排水-竣工图--自动喷水灭火系统原理图(二)`),
  目录只写后半段。**全等匹配实测只中 8 条(1%),改后缀匹配后 189 条**;多候选取标题最短者。

### 诚实的覆盖边界(决定了架构)

| | |
|---|---|
| 目录图 | 69 张 |
| OCR 提出的有效条目 | 377 条 |
| 能关联到实际图纸 | **189 张** |
| 条目对得上但查无此图 | 188 条 |
| **目录未覆盖的图纸** | **2051 张(占 89%)** |

**目录 OCR 太稀疏,只靠它排序会让 89% 的图乱序。** 故排序分三层
(migration 036,`sort_rank`/`directory_seq`/`sort_key`):

    0 目录图本身(按标题自然序)→ 1 目录列出的图(按目录顺序)→ 2 其余(专业 + 图号自然序)

第 3 层的图号自然序(`A-3-1` < `A-10-13.4` < `A-40-41` < `S-0-20-202.01C`)是图纸集
本来的编排依据,**覆盖 100%**,不会因 OCR 稀疏而乱。目录图之间也须用自然序——
字典序会把「图纸目录12」排在「图纸目录2」前面。

### 交付

- `GET /drawings/directory-tree?project_id=` 目录树(须声明在 `/{drawing_id}` 之前)
- `POST /projects/{id}/directory-rebuild` 重建(`dry_run=true` 只统计)
- 列表默认 `ORDER BY sort_rank, directory_seq NULLS LAST, sort_key`
- 前端 `DirectoryDrawer.tsx`:工具栏「图纸目录」按钮 → 右侧抽屉树,点图名直跳详情;
  **树顶显式写出「另有 2051 张未被目录覆盖」**,不让人误以为这棵树就是全部图纸

## 9.17 图框字段区域记忆(H20)——框一次、记住、跨项目复用

**需求**:① 未读到图框的图纸,预览里手工框选专业区域并更新,同步刷新同类型图纸;
② 图号/图名先按文件名,上传后自动用图框区域识别更新;③ **记住人工处理过的区域,
生成记忆辅助本项目及其他项目的相同信息识别**。

### 三级取值(前一级失败才走下一级)

| 级 | 手段 | 何时起作用 |
|----|------|-----------|
| 1 | **档案层文本** | 已有 OCR,零成本 |
| 2 | **区域重识别** | 该格的字没被全图 OCR 认出来——实测 **39 张有「专业」标签却读不出值**;裁小图 **300dpi** 重认(实测确实拿到了全图 OCR 漏掉的文字) |
| 3 | **人工拍板** | 重识别也糊了——实测「建筑」被认成「建 个人」。此时**不猜**:把区域原文摆给人,人选定即权威值 |

第 3 级是关键设计:词表校验不过时返回 `NEEDS_CONFIRMATION` + 原文,而不是静默写错值,
也不是简单报失败。**错的专业会误导筛选与规则引擎选型,比留空更糟。**

### 记忆库(migration 037 `title_block_templates`)

- 人框一次 → 区域按**页面高度归一化**存库(与 `drawing_transform`/人工轴线同口径)
- **同版式判定**用页面宽高比分桶(0.01 精度);同桶内按**命中次数**降序试,
  第一个读出合法值即采用——**用得越多排得越前,这就是记忆的强化**
- `project_id = NULL` 即**跨项目全局记忆**;查找顺序:本项目 → 全局
- `POST /projects/{id}/title-block/apply` 批量套用到尚未读到该字段的图纸

### 图号:不自动覆盖文件名(重要取舍)

实测**图框图号与文件名解析值只有 86% 一致**(样本 80),不一致的多是 OCR 字符级糊字
(`P-31-23`→`D-31-23`、`.01C`→`.010`、`IE-12-51`→`IE12-51`)。文件名是导入时的确定信息,
更可信。故**图号只在文件名没给出时才从图框补,绝不静默覆盖**。

为把图号读对,另加两项处理(`title_block_discipline`):
- **同行多 token 拼接**:图号常被切成 `IE-2` + `1-02.5` + `B`,只取最近一个会截断;
  按 x 累加,间距超过字高 3 倍即认为跨栏打住;
- **重叠去重**:OCR 会重复识别出互相重叠的 token(`IE-` + `IE-20-08` → `IE-IE-20-08`),
  取最大「后缀=前缀」重叠再拼。

英文标签也改成**模糊匹配**(difflib,阈值 0.72)——`DRAWING NO.` 被糊成
`DRAING/DRAMING/DRABING NO.`、`DISCIPLINE` 糊成 `DISCIFLINE/DISCIRLIE/BISCIPLIE`,
穷举写不完;同时加断言保证真实图号(`P-29-22`/`S-0-10-004`)不被误判成标签。

### 实测与边界

框选端到端已验证:`{"value":"给排水","page_aspect":1.42,"template_id":"87f8c521…"}`。

**如实说明**:用一张已读到的图的区域去套那 140 张,`updated=0`。诊断结论——
这 140 张里 **69 张是目录图**(本就没有专业栏)、**39 张图框内部版式不同**
(专业值不在标签正右方)。页面宽高比相同不代表图框内部布局相同。
**这正是记忆库的用法**:对每种版式各框一次,库里就会有对应模板,套用时逐个试即可命中。

## 9.18 标注统一走位图:PDF / CAD 也能标定(H21)

**问题**:轴线标定与图框框选原先只支持图片格式——PDF 走 iframe 由浏览器渲染,
拿不到坐标;CAD 虽已渲成 PNG,但那张是**建模贴图**,用固定画布 `(16,12)`,**会拉伸**。

**为什么拉伸致命**:标注的归一化坐标是「同除显示高度」,只有**等比**渲染才满足
`像素/图高 == 点/页高`,才对得上后端 `page_h` 口径。一旦宽高比被改,标出来的轴线
落到模型里就是错的位置。

`services/drawing_raster.py`(11 单测)给标注专用一条等比栅格通道:

- **PDF** → 150dpi 渲 PNG;超长边 6000px 时**等比降 dpi**(A0 图不爆内存),
  宽高比不变(单测直接断言 800×400 页渲出来仍是 2:1);
- **CAD** → 按图形实际范围算画布(`cad_figsize`),与建模贴图**分开存 key**,互不覆盖;
  DWG 先经 `dwg_support.ensure_dxf`(LibreDWG)转 DXF;
- 结果写回 MinIO **幂等缓存**:首次 1.6s,再次 25ms。

端点加 `?raster=true`(标注模式),前端两个标注组件都改走这条路。

### 顺带修掉的真问题:容器零字体

CAD 渲染一直报 `no fonts available, not even fallback fonts`——**容器里一个字体都没有**
(`findSystemFonts()` 返回 0)。这不是我这轮引入的,DWG 普通预览此前也是 422。
已在 `Dockerfile` 装 `fonts-dejavu-core` + `fonts-wqy-zenhei`(后者提供中文字形)。

**实测**:PDF / DWG 标注模式均返回 `image`;DWG 渲出 1600×418(宽高比 3.83,
**非**固定画布的 1.33),等比确认。DWG 普通预览也顺带修好了。

## 9.19 轴号格式扩展 · 合并重派 · 轴线记忆(H22)

**① 附加轴号**(`axis_label_sequence`,20 单测):原先只认纯数字/纯字母,
实际工程图大量使用 `1-1`、`2-10`、`A-1`、`B-20`、`A/3` 这类**附加轴号**(分轴线)。
顺推时**只递增分号部分,主轴号不动**(`1-1`→`1-2`,而非 `2-1`);主轴号仍受
I/O/Z 禁用约束;起止轴号的主轴号必须一致,否则报错。

**② 单条轴线合并重派**(`POST …/manual-axes/relabel`):单条标定时轴号一条条填,
难免填错或想改成连续序列。现在表格支持多选,选中若干条 → 按命名方向排序 →
用起止轴号统一重派。**旧轴号先删再写**,避免新旧混存。
实测 `1-1/1-2/1-3` → `A-1/A-2/A-3`,位置保持不变。

**③ 手描轴线记忆**(migration 038 `axis_line_memory`,12 单测):
候选线抽取会漏(点划线淡/被标注遮挡),人手描过的线记下来,
**同图重开、同版式换图都自动补进候选**(橙色区别于自动检出的灰线),不必重描。
与 `manual_axis_references` 分开存——前者是**结论**(带轴号,进建模参考系),
后者是**线索**(仅位置,补候选)。实测:自动检出 34 + 记忆补入 3 = 37 条候选。

## 9.20 修:框选后同类图纸刷不动(H20 补漏)

**用户实测反馈**:框选专业后,同类未识别图纸没有被刷新。

**根因**:`apply_templates` 只读**档案层文本**,没有 §9.17 里给单张加的
**区域重识别**兜底。而这些图纸「未读到专业」的原因**恰恰就是那格的字没被全图 OCR
认出来**——只查档案必然一张也补不上(实测 `updated=0`,当时我误判为「版式不同」)。

**修法**:批量套用改成与单张同样的两级——先档案文本(零成本),读不到再区域重识别。
重识别每张约 1s,故加 `ocr_budget`(默认 120)限量,并**如实报出
`ocr_used` / `ocr_skipped`**,预算用完提示「可再点一次」,而不是假装跑完了。

**交互也改了**:框选读到值后**自动触发**批量刷新(原先要再点一次按钮);
一张都没补上时明确提示「多半是这些图的图框版式不同,请到其中一张上再框一次」,
而不是静默显示 0。

## 9.21 交叉点定位:把整张图摆进工程坐标系(H23)

五项一起做,共同构成「从图上标注 → 整图世界定位」的闭环。

### ① 平移已标定轴线

`POST …/manual-axes/move`。传的是**「移到哪」而非「移了多远」**——反复微调不会
累积误差。角度保持不变(斜向轴线拖动后仍是原角度)。自动识别转存的、人工画的都能拖。

### ② 选点定轴(`axis_geometry.line_through_point`)

点一个点 + 写轴号对(如 `1轴-A轴`)→ 在该点**同时生成竖向与横向两条轴线**。
单测直接断言核心保证:**生成的两条线交点就是所点的那个点**。

### ③ 斜向轴线(`orientation` 三分)

原先 `axis_position` 对斜线返回 None,斜向轴线一律判为无效。实际放射柱网、异形平面
很常见。改为三分 `x / y / skew`,斜向位置用**法线式偏移**表示
(`axis_offset`,竖线退化为 x、横线退化为 y,与既有口径一致,排序不会反)。
DB CHECK 约束同步放行 `skew`。

### ④⑤ 交叉点定位(`drawing_anchor`,migration 039)

交叉点的身份是**轴号对**,这正是「多张图出现相同轴号」时的天然锚点。
**≥2 个点**即可用 Umeyama 闭式解求出**相似变换**(缩放 + 旋转 + 平移):

- **图↔图**(需求 4):两图有 ≥2 个同名交叉点 → 把 B 图整体摆到 A 图坐标系;
- **图↔世界**(需求 5):交叉点填工程坐标 XYZ → 解出整图到工程坐标系的变换。

**为什么是相似变换而不是仿射**:图纸等比绘制,允许缩放/旋转/平移但**不允许拉伸错切**。
放开会把识别误差吸收成假的形变,错得更离谱。

残差 RMSE 一并返回,超 0.5m 标 `suspect`——**点配错或轴号重名时照样能硬解出一个变换**,
必须暴露而不是当好结果用。

**每专业各定义一次原点**(`project_coordinate_origins`,UNIQUE(project,discipline)):
各专业图纸常用不同局部原点,共用一个会整体错位。接口**主动列出还没定义原点的专业**
(按图纸张数降序,先定义图多的收益最大),缺一个就点名,不静默。

### 实测

```
选点定轴 1轴-A轴  → axes_created ["1","A"]
斜向轴线 45°      → 保存成功
平移轴线 1 → x=0.4 → {"x1_norm":0.4,...} 角度不变
世界定位(2 点)    → scale 80.0 · rotation 0° · rmse 0.0m · suspect false
跨图对齐(2 同名点)→ scale 2.0 · rmse 0.0
专业原点          → 已定义 1/5,未定义 电气 1055 · 建筑 502 · 给排水 228 · 基坑围护 72
```
测试数据已清理。

## 9.22 修:批量刷新同版式图纸「失败」(H20 再补)

**用户反馈**:批量刷新同版式图纸失败。

**根因不是逻辑,是耗时**。实测 **5 张跑了 48 秒**——每张读不到档案就做区域重识别,
每次数秒;138 张要跑二十多分钟。同步 HTTP 请求必被前端超时掐断,用户看到「失败」,
**后端其实还在跑**。

三处修:

1. **改成 Celery 后台任务**(`tasks/title_block_apply.py`):POST 秒回 `task_id`,
   前端轮询 `GET …/apply/{task_id}` 取进度/结果;
2. **模板去重 + 限量**:人反复框同一格会攒出一堆近重复模板(实测 8 个里 5 个是同一格),
   逐个试把耗时放大数倍。按中心距去重,每张图最多试 3 个;
3. **拒绝过小框选**(`MIN_REGION_SIDE`):实测极小区域裁出来只有几像素,
   OCR 后端直接崩(`float division by zero`)。

**实测结果**:入队秒回,后台约 50s 跑完 52 张候选,**updated=6**;
未读到专业的图纸 **140 → 48 张**。

## 9.23 构件按工程坐标摆放(H24)

把 §9.21 解出的世界变换**真正接进建模流程**。

**最容易错的一步:坐标空间必须一致。** 交叉点存的是**归一化页面坐标**,
构件是**本图米坐标**(以该图轴网原点为原点)。解算前必须先用同一个
`drawing_transform` 把交叉点换算到米,否则解出的变换作用在构件上是错的。
单测直接钉死这一步:`0.2 页宽 → 10m`、`0.4 页高 → 30m`(含 y 翻转)。

**绝对优先于相对**:有工程坐标锚点的图按绝对坐标摆放,并**跳过相对轴号配准**——
否则会被相对平移拉离它的真实工程坐标。没有锚点的图保持原有相对配准行为。

**宁可不摆也不摆错**:
- 无 `drawing_transform` 或锚点不足 2 个 → 不在结果里,构件原样保留;
- 残差 `suspect`(>0.5m)→ **跳过摆放并记 warning**,不给它编一个位置。

`floor_meta` 同时报出 `placed`(绝对定位图数)与 `registered`(相对配准图数),
这一层到底有多少图是真定位、多少是相对贴合,一眼可见。

**实测链路**:2 个带工程坐标的交叉点 → 解出 `scale=0.3963 rot=0° rmse=0.0000m` →
构件坐标 `[0,0]` 被搬到工程坐标 `[77.541, 171.063]`,`placed=True`。

**当前边界(如实说)**:全项目 1392 张图有坐标变换,但**带工程坐标锚点的只有人工标过的那几张**。
要让整套模型都按工程坐标就位,需要先按 §9.21 给**每个专业**定义原点、
并在关键图上标出带坐标的交叉点。链路已通,数据要人喂。

## 9.24 系统自学习闭环(H25)——人工标注反哺自动识别

**目标**:每次人工标注都让系统变强,自动识别更准更全,人工量逐步下降。

### 闭环:标注 → 分析 → 建议 → 人审采纳 → 生效

四张表各司其职(migration 040):

| 表 | 职责 |
|---|---|
| `annotation_events` | 原始事件:人改了什么、系统原本猜的是什么——**学习的燃料** |
| `optimization_runs` | 每轮分析的**逐步过程日志**,可实时查看 |
| `improvement_suggestions` | 建议 + 人审状态 |
| `learned_rules` | **采纳后真正生效**的规则,被识别路径直接读取 |

**学习信号定义**:`auto_value`(系统当时的自动值)与 `human_value`(人给的值)的差异——
auto 空而 human 有值 = 覆盖缺口;两者不同 = 准确性缺口;两者相同 = 人只是确认,**不构成信号**。

### 五个分析器(`learning_analyzers.py`,18 单测)

| 分析器 | 学到什么 | 可自动生效 |
|---|---|---|
| 词表扩充 | 人反复填的专业词,系统词表没收录 | ✅ |
| OCR 纠错 | 稳定的糊字映射(实测「建 个人」→「建筑」) | ✅ |
| 阈值调整 | 手描比例过高 → 候选线门槛太严,按观测跨度反推新阈值 | ✅ |
| 版式缺口 | 同宽高比仍反复框选 → 版式指纹不足 | ❌ 需开发 |
| 比例尺分歧 | 自动值被系统性改掉 → 换算链路有偏差 | ❌ 需开发 |

**三条设计底线**:
1. **建议必带证据**——每条附样本与计数,人能当场核对凭什么这么说;
2. **区分可自动生效与需开发介入**——后者采纳只标为待导出,**系统行为不变**,
   界面上也分两个 Tab,避免让人误以为点了采纳问题就解决了;
3. **证据不足不出建议**(`MIN_EVIDENCE=3`)——凭一两次标注推规则会引入噪声,
   反而拉低下一轮准确率。

### 「采纳即生效」不是口号

已采纳规则被识别热路径直接读取(`learned_rules.py`,带 TTL 缓存,采纳时主动失效):
- 词表扩充 → `normalize_region_text` 认出新专业词;
- OCR 纠错 → 区域重识别文本先过一遍还原,**按原文长度降序替换**
  (短串可能是长串子串,先换短的会把长的拆坏);
- 阈值 → 候选轴线最小跨度等参数覆盖,坏值自动回落内置默认。

**实测硬证据**(采纳「建 个人 → 建筑」后):

```
不带学习规则: normalize_region_text('专业 建 个人') → None
带学习规则  : normalize_region_text('专业 建 个人') → 建筑
```

### 一轮真实运行

```
扫描 18 条标注 → by_kind {scale:4, axis:5, discipline:9}
分析产出 5 条 → {vocabulary:2, ocr_correction:1, threshold:1, algorithm:1}
其中可自动生效 4 条,需开发 1 条
```

建议样例(界面直接展示证据):
- `[可自动生效] 影响5 置信0.95 | 专业词表补录「舞台机械」`
- `[可自动生效] 影响4 置信0.88 | OCR 纠错「建 个人」→「建筑」`
- `[可自动生效] 影响4 置信0.80 | 放宽候选轴线最小跨度至 0.162`
- `[需开发介入] 影响4 置信0.60 | 比例尺自动值与人工确认不一致 4 次`

**导出**:`GET …/optimization/export` 产出结构化包——**只含需开发介入的条目** +
完整证据 + 过程日志,可直接提交开发。演示数据已清理。

## 9.25 修:超大图上框选报「区域为空」+ 预览太糊(H26)

**用户实测**:`P-22-02B 消火栓系统原理图(二)` 点框选后报 `EMPTY_REGION`,
且标注用的预览明显比直接预览糊。

**根因是同一个**:这张图是 **5084×2412pt 的加长图**(远超 A0),而我两处门槛
都是按普通图幅拍的:

| | 我拍的值 | 这张图上的实际情况 |
|---|---|---|
| 最小框选边长 | 归一化 **0.01** | 「给排水」那格只有 **0.0046×0.0030**——必然判空 |
| 栅格最长边 | **6000px** | 150dpi 要 10592px → 被降到 **84dpi**,「专业」二字只剩 **7px** |

### 修法

**① 最小框选改按物理尺寸(pt)判,不再用归一化比例。**
字段格的物理大小与页幅无关(永远几毫米),所以门槛必须是 `MIN_REGION_PT = 3.0`,
按页高换算成归一化。单测把这个道理钉死:同一个归一化尺寸
`0.0046×0.0030`,在 2412pt 的加长图上物理 7.2pt **应放行**,
在 595pt 的 A4 上物理只有 1.8pt(比字还小)**应判无效**。

**② 栅格上限 6000 → 12000px。**
实测这张图 200dpi 也只有 **1.5MB / 3.2s**——线稿 PNG 压缩极好,
提高上限的代价远小于「看不清」的代价。现在跑满 150dpi,「专业」二字 12px。
A0(3370pt)也不再被降,保持全分辨率。

**已清除 21 张旧的低清缓存**,否则幂等缓存会一直供旧图。

### 实测

```
栅格重渲 → 150dpi · 1.00MB · 1.5s
框选那一格(0.0110×0.0065)→ {"value":"给排水","raw_text":"给排水 P-22-02B"}
```
按旧门槛这个框(高 0.0065 < 0.01)会被直接拒掉。

## 10. 诚实的能力边界

- 无图层扫描 PDF 的自动识别上限有限;本方案靠**人审收敛**保证最终准确,不承诺纯自动完美。
- `drawing_transform` 覆盖率(705/2309)是当前短板;H2 需先补变换回填 / 用轴网格兜底关联。
- **配准覆盖(item 2 已改进)**:诊断发现大歌剧院轴网检测≈0(几乎所有层 axes x=0/y=0,少数层仅 x
  无 y)→ 完整双向网格键无从构成。改进:单轴部分配准 `X-?` 记录为 grid_ref(供覆盖/追溯),
  **但不作合并键**(带 ? 走米坐标兜底,防单轴狂并——实测总数仍 8094、单实体最多观测仍 18)。
  **with_grid 覆盖 0 → 2252(27.8%)**。诚实:仍是部分配准,**完整配准需上游轴网检测(双向)改进**,
  是数据/检测短板,非装配可独立解决。
- 大模型职责限定在「读意图/仲裁/分区」,**不允许其虚构几何**,一切几何须有图纸观测支撑。
- 每个构件、每次人审动作、每条 Z 值都带 provenance,可审计、可回滚。
